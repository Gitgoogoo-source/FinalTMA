# ADR-079：藏品详情稀有度与战斗力同行布局

- 状态：已接受
- 日期：2026-08-23

## 背景

真实 iPhone Telegram 藏品页把稀有度放在名称下方，同时允许 768px 藏品详情图在英雄区内以底部为锚点放大并向上自然溢出。体型较高的透明素材因此进入名称区域下沿，稀有度文案虽然仍处于标题层，但视觉上已经压在藏品大图顶部。问题来自两个有效布局规则占用同一位置，不是图片资源、稀有度数据或详情图解码错误。

产品已经确认名称区域不再承载稀有度，稀有度必须移动到下方战斗力数值之后。该调整只改变共享藏品详情的信息排列，不改变任何目录、库存、战斗或图片规则。

## 决策

`CollectionDetailShowcase` 的名称区域只渲染藏品名称和条件成立时的 NEW 提示，不再创建 `.inventory-title-rarity`。详情数值行固定由两个信息组组成：左侧显示进化阶段，右侧依次显示战斗力标签、完整战斗力整数、中点分隔符和当前语言的稀有度文案，即“进化阶段｜战斗力数值 · 稀有度”。

稀有度文案继续使用原名称下方文案的灰色、字重和字号等级，不增加稀有度色块、徽章或新图标。数值行按内容宽度居中，两组使用内容宽度列，最大宽度限制在页面安全范围内，使英文 `Legendary` 与其他五档文案均保持单行。右侧信息组的无障碍名称同时包含战斗力标签、完整数值、稀有度标签和稀有度文案；中点只用于视觉分隔，不重复朗读。

## 不变量

- 名称、进化阶段、战斗力和稀有度仍来自当前选中模板的同一权威详情数据，不在前端推导或改写。
- 藏品主图尺寸、底部锚点、`scale(1.16)`、缩略图预览、详情图解码替换和预热规则保持不变。
- 技能条、数量状态、NEW 条件、操作按钮、筛选、缩略图和底部导航保持不变。
- 模板切换只更新本地展示，不因本布局新增 API 请求、数据库访问或持久化写入。

## 验收

影响域必须通过 Prettier、ESLint、Web TypeScript、架构检查和生产构建；发布前执行全量 `validate:static`。同一部署 SHA 的真实 iPhone Telegram 必须依次检查五档稀有度，确认名称与主图之间不再出现稀有度，且“战斗力数值 · 稀有度”完整位于主图下方数值行，无重叠、换行或截断。Safari Web Inspector 在独立轮次确认标题 DOM 不含旧稀有度节点、战斗力信息组的 DOM 顺序与无障碍名称正确；静态检查、普通浏览器和部署 READY 不能替代真机结论。
