# ADR-020：Battle 全流程红宝石式 GBA 对战视觉

## 状态

已接受。

## 背景

Battle 的九种页面状态需要形成统一、可直接上线的移动端对战体验。功能、资产与战斗结果继续完全服从现有 Battle 契约；视觉和交互采用 2000 年代早期 GBA 宠物对战游戏的画面组织方式，并保留 PokePets 已有高清宠物美术。

## 裁决

Battle 全流程固定使用深青描边、奶油色信息面板、薄荷绿战场、青绿色指令条、橙红色选择反馈和硬边阴影。卡片与弹层使用小圆角或直角，不使用玻璃拟态；按钮保持至少 44px 触控高度，并计算 Telegram 顶部、底部与左右安全区。

`home`、`team_select`、`preparing_share`、`waiting`、`accept`、`lobby`、`battle`、`forced_switch` 与 `result` 共用上述视觉语言。`battle` 与 `forced_switch` 隐藏应用顶部资产栏和共享底部导航，进入仍计算 Telegram 原生控件与设备安全区的沉浸式布局。战斗页延续 GBA 单宠 1v1 构图：对手状态位于左上、对手宠物位于右上、己方宠物位于左下、己方状态位于右下；技能使用两列奶油色指令卡，主动换宠使用整行青绿色按钮。当前回合、服务端倒计时、动作提交、锁定和结算状态始终以明确文字展示。

宠物只使用项目正式 768px 详情图与 256px 缩略图。战场背景使用项目资源 `/assets/battle/ui/ruby-arena-field.webp`；首页装饰使用正式宠物资源。不得复制或引入 Pokémon 图片、精灵、图标、音频、文字商标、PokeAPI 或第三方战斗代码，也不得用内联 SVG、CSS 图形或占位符伪造宠物与场景资源。

界面动画只表达前端即时反馈：宠物位移、命中震动和状态切换可以立即播放，但命中、伤害、击倒、换宠、胜负、退款与到账只消费 viewer-specific 服务端权威结果。`prefers-reduced-motion` 下停止非必要循环与位移动画，业务时序保持不变。

## 结果

Battle 的功能范围、九种状态、接口、金额、权限、幂等、库存占用、错误处理与数据库裁决全部保持不变；本 ADR 只冻结全流程视觉系统、真实资源使用方式和移动端交互表现。
