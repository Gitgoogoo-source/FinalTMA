# ADR-033：邀请分享只保留本地反馈

## 结论

任务中心继续提供“复制邀请链接”和“Telegram 邀请”按钮，但两个动作只产生当前页面的即时本地反馈，不再是每日任务，不发放 5 或 10 Gems，也不调用 FinalTMA API、PostgreSQL RPC、operation 恢复、任务刷新或资产刷新。

复制成功只显示“链接已复制”；复制失败显示“复制失败，请重试”。Telegram 分享按钮继续打开原生分享界面，打开成功保留原有本地反馈，不支持或调用失败时显示既定可理解提示。任何本地反馈都不证明消息已经送达、邀请已经绑定、好友已经充值或奖励已经到账。

真实邀请候选、一次性绑定、首次有效充值后邀请人 500 Gems、UTC+0 每日 20 人上限、账号生命周期 300 人上限，以及 5/10 位有效充值好友阶梯奖励全部保持不变，继续由 Telegram 入口交接、支付交付事务和 PostgreSQL 唯一事实裁决。

## 删除边界

- 从服务端固定任务定义中删除 `copy_referral` 与 `telegram_invite`，其 5/10 Gems 奖励不迁移到其他任务。
- 删除 `referral.share_event` REST 契约、路由处理器、OpenAPI 路径、RPC、安全 allowlist、错误码、前端 operation 注册和恢复文档。
- 删除任务分类中的“社交”及两张任务卡、任务跳转和任务高亮依赖。
- 不删除邀请链接、分享文案、两个按钮、邀请统计、绑定、首充奖励、奖励上限或阶梯奖励。

分享动作不再触发任何服务端写入，因此重复点击、并发点击、跨日和重开应用都不会产生任务进度、账本或待恢复 operation；页面反馈只保存在当前运行内存。
