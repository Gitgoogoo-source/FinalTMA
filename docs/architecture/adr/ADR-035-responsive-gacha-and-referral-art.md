# ADR-035：抽卡与邀请插画响应式 WebP

## 状态

已接受。

## 决定

抽卡首页不再把三张箱子主图同时挂载为高优先级图片。页面只渲染当前选中箱子的主图，并固定使用 `loading="eager"`、`fetchpriority="high"`；未选中箱子的主图不进入 DOM。鼠标或触控指针进入、按下选择器，以及键盘焦点进入选择器时，只预取该档箱子的响应式主图；切换选择后，新主图成为唯一高优先级图片。选择器缩略图继续存在，但只读取缩略尺寸资源，不能通过原始箱子 URL 下载大图。

箱子主图的 CSS 展示盒最大为 284×276 px，动画最大缩放 1.2 倍，选择器与签到缩略图最大为 50×50 px。三个箱子分别从既有正式 WebP 生成以下宽度，保持原始宽高比、透明通道与完整构图：

| 用途               | 响应式宽度        | WebP 编码                                              |
| ------------------ | ----------------- | ------------------------------------------------------ |
| 选择器与签到缩略图 | 128、192 px       | quality 82、alphaQuality 100、effort 6、smartSubsample |
| 当前选中主图       | 384、768、1024 px | quality 82、alphaQuality 100、effort 6、smartSubsample |

主图 `sizes` 固定为 `(max-width: 430px) 89vw, 341px`，将动画缩放后的最大可见宽度计入候选选择；缩略图 `sizes` 固定为 `50px`。浏览器不支持候选资源或响应式资源加载失败时，当前元素移除 `srcset` 并仅回退一次既有原始箱子 WebP；原始资源再次失败后维持既有不可操作状态，不能循环重试或反复下载。

邀请礼盒在约 200×160 px 的展示盒中使用 256×192、512×384、768×576 三份响应式 WebP，固定使用 quality 86、effort 6、smartSubsample，保持 4:3 构图且不裁切。运行时代码不再把 PNG 作为正常路径；只有 WebP 加载失败时才回退既有 PNG。本决定覆盖任何要求邀请礼盒必须以 PNG 作为当前运行时正常路径的旧约束，不裁决旧源文件的后续清理。

所有变体使用项目锁定的 Sharp 与 Lanczos3 从正式源文件确定性缩放，移除非必要元数据。箱子资源位于 `/assets/boxes/responsive/`，邀请资源位于 `/assets/tasks/`；文件名包含像素宽度，同一部署内的 `src`、`srcset` 与公开文件必须原子发布。

## 一致性与失败处理

加载策略只改变静态图片传输，不改变箱子档位、概率、价格、免费资格、保底、签到奖励、邀请奖励、API 或数据库权威。程序化选择、URL 恢复、免费稀有箱自动选择和充值恢复仍直接加载当前选中档位，并在图片成功解码前保持既有操作禁用条件。

资源门禁固定校验十八份 WebP 的容器、精确宽高、Alpha 要求、单文件字节上限，以及 Vite 构建复制结果与源文件 SHA-256 一致。任一文件缺失、尺寸错误、透明通道错误、超过预算或构建副本不一致时停止发布。

## 验证

影响域静态验证包括 Web 类型检查、格式检查、资源门禁和生产构建。构建成功只能证明资源和代码完整，不能证明真实 Telegram WebView 的网络优先级或肉眼清晰度。自动部署完成后必须在真实 Telegram Mini App 中分别复核默认箱子、触控切换三档、键盘焦点预取、七日签到稀有箱和邀请礼盒；若资源失败，必须确认只发生一次原图回退且业务按钮不会在主图未加载时启用。
