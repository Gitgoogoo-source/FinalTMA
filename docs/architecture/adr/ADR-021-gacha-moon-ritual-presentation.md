# ADR-021：开盒灵契黑洞特效、结果舞台与展示门控

## 决定

开盒进行态由按意图加载的 `OperationRegistryRuntimeProvider` 统一渲染 `GachaHatchAnimation`；入口中的轻量 `OperationRegistryProvider` 只负责在重型运行时就绪前锁定并交接首次操作。弹层位于 `AppShell` 外层，使用独立的全局组件类，不依赖 `.app-shell` 后代选择器。召唤、图片失败重试和结果舞台共同挂载 `GachaAstralBackdrop`：它只由 CSS 渐变、静态金色星尘和深黑远空组成，不读取背景图片。召唤阶段在该背景上叠加 ADR-067 的 WebGL2 灵契黑洞与螺旋吸入粒子；结果阶段保留同一深黑金色空间层级并停止粒子运动，使金光爆发后的画面稳定承接真实结果。最终结果只读取公开 `pet-runtime` 中的真实宠物图片，效果图不参与帧合成。

玩家点击一次后，动画自动运行且不可跳过。正常路径固定为前 `4000ms` 中性汇聚和后 `700ms` 结果揭晓：前段在屏幕视觉中轴形成小型深黑核心，黑洞严格完成 13 次完整呼吸，单次周期依次为 `800 / 580 / 460 / 380 / 330 / 290 / 260 / 230 / 200 / 170 / 130 / 100 / 70ms`；每次先膨胀再收缩，下一轮低点和高点均继续增大，使整体持续长大，最后四轮在 `470ms` 内以只作用于黑洞尺寸与事件视界光环的极速临界频闪完成蓄能，最终扩大到约占窄屏宽度一半的临界直径。周围香槟金粒子从外圈沿切向旋转并逐步收紧半径，以清晰弧形轨迹被吸入事件视界，吸积环和金色尘流同步增强。该阶段只使用深黑、暖金、香槟白与低饱和棕金，不读取盲盒档次或提前返回的结果。到达 `4000ms` 时，如果服务端终态以及单抽唯一详情图或十连初始中央缩略图已经准备完成，运行时才把单抽唯一结果或十连最高结果的真实稀有度传入最后 `700ms`；最后阶段以金色为主体并叠加少量真实稀有度色调，显示全屏金光、放射光线、扩散冲击环和画面冲击，再整体显现真实结果，不改变结果排序、概率、随机、扣款、资格、保底、藏品或任何服务端结算。

如果到达 `4000ms` 时 operation 仍未取得终态，或者成功终态已经到达但本次揭晓门槛图片仍未完成浏览器解码，动画冻结在不含稀有度的最大黑洞临界画面，不重新呼吸、不继续吸入、不显示进度文案，也不推测结果。当前前台运行期查询原 operation 回正且单抽唯一详情图或十连初始中央缩略图准备完成后，才从该临界画面播放一次 `700ms` 金光爆发和冲击揭晓；因此正常路径为 4.7 秒，慢响应路径只延长临界停留。明确失败终态或揭晓门槛图片最终失败同样在临界门控后执行一次不含稀有度的中性金光收束，再展示真实失败或图片重试舞台。

五核及以上设备的前三次中性触觉使用 Telegram `selectionChanged()`，揭晓触觉只在稀有度已经允许公开后使用 `impactOccurred()`；声音继续由 Web Audio 现场合成，中性阶段为逐步增强的吸入风噪、上升低频和三次呼吸脉冲，揭晓阶段为随真实稀有度增强的金光爆发撞击与高频尾音，不读取音频文件，能力缺失时静默降级。四核及以下设备固定不创建或播放自定义 Web Audio，也不触发开场、服务端成功或揭晓的 Telegram `HapticFeedback`，避免真实 iPhone Telegram 的原生触觉桥接和 Safari 音频管线阻塞可见动画；结果舞台中的后续用户交互仍保留普通控件反馈。WebGL2 普通设备、四核及以下、减少动态效果和 Canvas 2D 降级的固定上限由 ADR-067 裁决。

成功结果由 `GachaResultDialog` 在静止的同一灵契星域上渲染。单抽使用当前资源批次的 `image_detail_url`，完整展示藏品名称、稀有度文字、对应 1 至 5 枚稀有度星印、NEW、稀有度光环和落点；宠物主图与上述身份信息在撞门光爆后执行一次不超过 `900ms` 的英雄式定格入场。十连使用全部 10 张 `image_thumbnail_url`，复制结果后仅在展示层按稀有度降序、同稀有度按 `order` 升序，再将第 1 至第 10 名依次放入轮播位置 `5 → 6 → 4 → 7 → 3 → 8 → 2 → 9 → 1 → 10`。十连按 ADR-068 在演出层后方以最终效果预绘制中央项，并以近透明状态预热其他已解码图层的首次纹理，结果层从准备到可见保持同一绝对定位和根合成层并使用无滤镜的静态深黑背景；金光交接不重启中央项、标题、身份或按钮动画，第一张结果帧固定同时显示中央主图、身份、标题和按钮，其余已解码结果再按中心向外顺序每帧最多加入一个景深层。只有当前中央项完整显示名称、稀有度和星印。轮播、触觉、按钮和只读展示规则保持不变；“确定”和“去藏品查看”只处理当前内存展示，“再开一次”才创建新的开盒 operation。

默认开盒页的规则、身份摘要和当前盲盒主图全部就绪后，页面立即通过既有动态加载边界准备开盒 Runtime 与表现 chunk，并按 [ADR-069](ADR-069-gacha-renderer-prewarm-and-static-stage.md) 在空闲时段预热并保留同质量档的真实 Canvas/WebGL 资源；程序化黑洞与粒子场不产生额外图片请求，也不把表现代码并入首屏同步闭包。按钮的 `pointerdown`、键盘 `focus` 和真实提交继续复用同一加载 Promise，因此首次点击直接租用已经预热的 Canvas 进入黑洞汇聚舞台，不显示浅色通用处理页。结果舞台的“再开一次”创建新 `operation_id` 时，只要当前内存中已加载的表现模块仍与 `gacha.open` 路由匹配，就直接复用该模块和单实例渲染池并让新序幕立即挂载；`operation_id` 继续只隔离业务状态、图片门控和揭晓计时，不得使同一路由回退到通用处理层。请求与首轮动画同时开始；成功终态先保存在内存，前三轮中性呼吸的 `1840ms` 独占窗口结束后只使用脱离 DOM 的 `Image` 准备单抽详情图或十连全部缩略图，不创建结果布局和合成层。4 秒中性呼吸完整结束并停在最大临界帧后，`GachaResultDialog` 才在动画层后方以 `aria-hidden`、`inert`、不可交互和较低堆叠层级真实挂载。单抽正式详情图或十连初始中央缩略图以 `HTMLImageElement.decode()` 成功作为揭晓就绪事实；十连其余九图仍并行加载和解码，但只按 ADR-068 在首张结果帧后逐帧加入。结果节点在完全不透明的演出层后方按最终尺寸预绘制，从挂载到可见不改变绝对定位、不重启十连首帧元素动画，金光结束后沿用原图片节点，不在切换帧首次构建十个复杂图层。

结果图片沿用 `CatalogImage` 的首次读取及 1 秒、3 秒两次有限重试，但开盒结果不显露通用宠物剪影。单抽唯一详情图或十连初始中央缩略图最终失败时，结果节点继续由演出层覆盖，运行时切换到静止的同一深黑金色灵契舞台，只显示 `月下灵契`、`灵契尚未显现` 和 `再试一次`。玩家重试仅增加同一 `operation_id` 的图片 `retryEpoch`，绝不调用 `gacha.open`、operation 查询或确认端点，也不触发资产、资格、保底、库存、图鉴、任务或 NEW 写入。

遮罩承担背景交互隔离，领域操作和底部导航继续使用既有 operation 锁。动画阶段不提供点击、蓄能、跳过或其他交互入口；结果阶段只有十连结果横向轮播及既有确认按钮可交互。动画节点不显示价格、扣款、资格、盲盒主图、藏品、保底、成功或失败结论，不参与业务状态计算。
