# ADR-021：开盒月夜灵契代码特效、结果舞台与展示门控

## 决定

开盒进行态由按意图加载的 `OperationRegistryRuntimeProvider` 统一渲染 `GachaHatchAnimation`；入口中的轻量 `OperationRegistryProvider` 只负责在重型运行时就绪前锁定并交接首次操作。弹层位于 `AppShell` 外层，使用独立的 `gacha-moon-*` 全局组件类，不依赖 `.app-shell` 后代选择器。仪式只读取一张不含闭合晶壳的静态月夜庭院 WebP 作为场景底图，不再通过闭合图、开启图或逐帧图片交叉切换制造特效；镜头推进、环境压暗、能量核、三次脉冲、水波、光环、晶壳、晶格、裂纹、晶壳分离、闪光、闪电与稀有度爆发全部由 CSS 时间轴、内联 SVG 和 Canvas 2D 实时绘制。最终结果继续只读取公开 `pet-runtime` 中的真实宠物图片，图片不参与动画帧合成。

玩家点击一次后，仪式自动运行且不可跳过。正常路径固定为前 `3300ms` 中性蓄能和后 `700ms` 结果揭晓：前三次脉冲、粒子、裂纹和声音只使用暖白与暖金，不读取盲盒档次颜色，也不泄露稀有度；到达 `3300ms` 时，如果服务端终态和本次全部结果图片都已准备完成，运行时才把本次结果中的最高稀有度传入最后 `700ms`。单抽使用唯一结果稀有度，十连使用十个结果中的最高稀有度；普通、稀有、史诗、传说、神话分别使用象牙白、生命绿、紫金、赤金、黑金强度，控制 Canvas 粒子、SVG 闪电、CSS 光爆、Web Audio 合成音和 Telegram `impactOccurred()` 强度。稀有度只改变最后 `700ms` 的表现，不改变结果排序、概率、随机、扣款、资格、保底、藏品或任何服务端结算。

如果到达 `3300ms` 时 operation 仍为 `confirming`、`submitting`、`pending` 或 `unknown`，或者成功终态已经到达但结果图片仍未完成浏览器解码，动画冻结在不含稀有度的临界裂纹画面，不重新循环、不显示进度文案，也不推测结果。当前前台运行期查询原 operation 回正且全部图片准备完成后，才从该临界画面播放一次 `700ms` 稀有度揭晓；因此正常路径为 4 秒，慢响应路径只延长临界停留。明确失败终态或结果图片最终失败同样在临界门控后执行一次不含稀有度的中性 `700ms` 收束，再展示真实失败或图片重试舞台。

三次蓄能触觉固定使用中性的 Telegram `selectionChanged()`；揭晓触觉只在稀有度已经允许公开后使用 `impactOccurred()`，能力缺失或客户端抛错时静默降级。声音由 Web Audio 振荡器、增益包络和现场生成的短噪声合成，不读取音频文件；开盒点击在用户手势内尝试解锁音频上下文，浏览器拒绝、系统输出静音或能力缺失时静默无声，不阻塞 operation、动画门控或结果展示。Canvas 像素比在普通设备上封顶 `1.75`，四核及以下设备封顶 `1.25`，粒子数量分别固定为 `64` 和 `38`；系统启用减少动态效果时只绘制 `18` 个静态光点和临界晶壳，关闭 CSS、SVG、Canvas 动画及稀有度爆发，但仍保留同一 `3300ms + 700ms` 展示门控。

成功结果由 `GachaResultDialog` 在开启后的月夜庭院背景上渲染。单抽使用当前资源批次的 `image_detail_url` 居中展示一个透明背景藏品主图；十连使用全部 10 张 `image_thumbnail_url`，复制 `result.results` 后仅在展示层按稀有度降序、同稀有度按 `order` 升序，再将排序后第 1 至第 10 名依次放入轮播位置 `5 → 6 → 4 → 7 → 3 → 8 → 2 → 9 → 1 → 10`。不循环横向轮播使用透明滚动轨道和 CSS Scroll Snap 承接手势、键盘切换与吸附；十个藏品同时绝对定位在一个舞台内，依据当前中央位置连续计算水平偏移、缩放、不透明度和层级。中央选中索引变更时调用一次 Telegram `HapticFeedback.selectionChanged()`，初始居中不触发；能力缺失或客户端抛错时静默降级。每项仅渲染稀有度文字、NEW 和主图；展示排序不回写 result，不发送结果确认请求，也不改变 NEW 写入或后端结算。“确定”和“去藏品查看”只处理当前内存展示，“再开一次”才创建新的开盒 operation。

新提交的开盒操作在前端以 `operation_id` 独立记录动画档次、`3300ms` 临界门控、`700ms` 揭晓门控、结果图片状态和图片重试轮次，不使用临时 request input、Canvas、音频、触觉或图片状态作为业务裁决。请求与首轮动画同时开始；成功终态使 `GachaResultDialog` 在仪式层后方以 `aria-hidden`、`inert` 和 CSS 隐藏状态真实挂载，实际结果图片节点立即请求当前公开桶 URL。单抽的一张详情图或十连的全部十张缩略图分别调用 `HTMLImageElement.decode()`；只有全部 Promise 成功、临界门控已到达且 `700ms` 揭晓已经完整结束时，才在不重建这些图片节点的前提下移除隐藏状态并整体显现结果。资源提示、`load` 事件和 `decoding="async"` 属性都不是就绪事实。页面隐藏、Telegram `deactivated`、`pagehide`、刷新、WebView 重载或重新认证立即清除该 operation 的动画、图片准备和结果展示；再次进入只显示开盒首页和最新权威状态，不恢复终态或未决召唤舞台。

结果图片沿用 `CatalogImage` 的首次读取及 1 秒、3 秒两次有限重试，但开盒结果不显露通用宠物剪影。任一图片最终失败时，隐藏的结果节点继续不可见，运行时在中性收束后切换到使用开启背景的静态 `GachaImageUnavailable` 舞台，只显示 `月下灵契`、`灵契尚未显现` 和 `再试一次`。玩家重试仅增加同一 `operation_id` 的图片 `retryEpoch` 并重建本轮图片节点，绝不调用 `gacha.open`、operation 查询或确认端点，也不触发资产、资格、保底、库存、图鉴、任务或 NEW 写入。重试中保持静态失败舞台并禁用按钮；全部图片解码成功后显现既有权威结果，再次最终失败则恢复同一重试入口。

遮罩承担背景交互隔离，领域操作和底部导航继续使用既有 operation 锁。动画阶段不提供点击、蓄能、跳过或其他交互入口；结果阶段只有十连结果横向轮播及既有确认按钮可交互。动画节点不显示价格、扣款、资格、盲盒主图、藏品、保底、成功或失败结论，不参与业务状态计算。
