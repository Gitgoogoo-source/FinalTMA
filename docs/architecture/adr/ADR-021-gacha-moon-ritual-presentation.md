# ADR-021：开盒月夜灵契动画、结果舞台与展示门控

## 决定

开盒进行态由 `OperationRegistryProvider` 统一渲染 `GachaHatchAnimation`。弹层位于 `AppShell` 外层，使用独立的 `gacha-moon-*` 全局组件类与全屏月夜庭院背景，不依赖 `.app-shell` 后代选择器。场景以闭合和开启两张版本化 WebP 背景在同一个 3 秒 CSS 周期中交叉切换，不使用服务端返回数据生成动画帧，也不修改 `gacha.open` 请求、响应或恢复契约。

仪式中只显示月夜庭院、蛋形灵契晶壳、灵光、固定标题与固定底部文案。三档盲盒共用同一视觉，不渲染盲盒蛋或当前档次盲盒主图，不以颜色、藏品或临时稀有度预告结果。场景不提供点击、蓄能、跳过或其他交互入口；每轮在固定时点调用三次中性 Telegram `selectionChanged()` 反馈，能力缺失或客户端抛错时静默降级。

成功结果由 `GachaResultDialog` 在开启后的同一月夜庭院背景上渲染。单抽使用 `image_detail_path` 居中展示一个透明背景藏品主图；十连复制 `result.results` 后仅在展示层按稀有度降序、同稀有度按 `order` 升序，再将排序后第 1 至第 10 名依次放入轮播位置 `5 → 6 → 4 → 7 → 3 → 8 → 2 → 9 → 1 → 10`。不循环横向轮播使用透明滚动轨道和 CSS Scroll Snap 承接手势、键盘切换与吸附；十个藏品同时绝对定位在一个舞台内，依据当前中央位置连续计算水平偏移、缩放、不透明度和层级。中央选中索引变更时调用一次 Telegram `HapticFeedback.selectionChanged()`，初始居中不触发；能力缺失或客户端抛错时静默降级。每项仅渲染稀有度文字、NEW 和主图；展示排序不回写 result，不进入确认请求，也不改变 NEW 写入、恢复或再次开盒行为。

新提交的开盒操作在前端以 `operation_id` 独立记录动画档次和周期边界，不使用会被恢复摘要替换的临时 request input 作为展示门控。请求与首轮动画同时开始；成功或失败终态只在首轮结束后的第一个周期边界开放展示。周期边界到达但 operation 仍为 `confirming`、`submitting`、`pending` 或 `unknown` 时，继续下一轮；终态在后续轮次中到达时，于该轮结束后切换到既有真实结果或失败弹窗。同一 operation 被恢复查询回正时不得清除本地周期门控。页面恢复到已经存在的终态 operation 时直接展示真实结果，不伪造一次新的开盒过程；恢复到未决 operation 时继续显示无结论动画和既有轮询恢复。

动画与成功结果舞台共用同一开启后的背景资源；遮罩承担背景交互隔离，领域操作和底部导航继续使用既有 operation 锁。动画阶段不提供交互入口；结果阶段只有十连结果横向轮播及既有确认按钮可交互。动画节点不显示价格、扣款、资格、盲盒主图、藏品、稀有度、保底、成功或失败结论，不参与业务状态计算。启用系统减少动态效果时，场景固定显示开启后的月夜灵契舞台，不展示盲盒主图；轮播滚动、位置吸附和按钮仍可使用，结果展示仍遵守同一个 3 秒周期门控。
