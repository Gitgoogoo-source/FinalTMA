# ADR-067：开盒 WebGL 灵契黑洞渲染边界

## 决定

开盒动态主体固定由按需加载的 `GachaAstralFieldRenderer.ts` 独立渲染，不引入 Three.js、PixiJS、Lottie、视频、透明序列帧、粒子贴图或第三方特效运行时。视觉节奏采用已经由用户裁决的“黑洞呼吸式成长、金色粒子螺旋吸入、全屏金光爆发、结果稳定”结构；所有 GLSL、几何、颜色、文案和合成音均为本项目原创，只参考用户提供画面的深黑暖金材质、中央构图和神秘氛围，不复制其素材、装饰、图标、界面或具体镜头。

主路径使用 WebGL2 和内置 GLSL ES 3.00 着色器，分为全屏黑洞场和螺旋粒子几何两个程序。全屏场绘制深黑远空、低饱和棕金云尘、事件视界、香槟金光子环、旋转吸积流和揭晓冲击环；粒子几何使用确定性种子生成外圈初始角度、深度相位、尺寸和吸入速度，每个粒子按“半径持续收紧、方位角持续增加”的轨迹接近事件视界，光迹方向由径向吸力和切向速度合成，因此运动轨迹明确为弧线而非直线。前 `3300ms` 的黑洞严格完成 9 次完整收缩与膨胀，单次周期依次为 `700 / 560 / 450 / 370 / 310 / 270 / 240 / 210 / 190ms`；每轮低点和高点的基准半径都大于上一轮，因此整体持续长大，同时后半段明显加速。粒子速度、光迹和吸积环亮度随进度增强，但只使用中性深黑、暖金和香槟白，不读取盲盒档次，也不泄露稀有度。最后 `700ms` 才把已经允许公开的真实稀有度以少量色调混入金色主体，并同步绘制金色全屏爆光、放射光线和扩散冲击环。到达临界门控而结果或图片未准备完成时，黑洞和粒子冻结在最大中性临界帧，不循环、不继续运动。

普通设备固定使用 `520` 条 WebGL 螺旋粒子并将设备像素比封顶 `1.25`；`hardwareConcurrency <= 4` 固定使用 `320` 条粒子、关闭多重采样抗锯齿并将设备像素比封顶 `1`。系统启用减少动态效果时只绘制一次由 `96` 个静态金色粒子、最大黑洞和吸积环组成的临界帧，不继续请求动画帧、不播放稀有度爆发。WebGL2 创建失败时，同一个 Canvas 使用 Canvas 2D 同构降级：普通、四核及以下和减少动态效果分别使用 `180 / 120 / 48` 条螺旋粒子或静态粒子，并保留黑洞、吸积弧和金光爆发。WebGL 程序已经创建后如果运行期上下文丢失，既有 4 秒门控仍继续进入权威结果，不重试业务请求或推测结果。

渲染器的 React 包装只在表现组件挂载时创建一次 WebGL context、program、buffer 和 vertex array；进入揭晓阶段时只更新同一实例的时间轴与稀有度颜色，以 `3300ms + 当前揭晓时间` 继续同一确定性星轨相位，不得因 React 状态切换重新编译着色器、重建缓冲区或让星轨跳回起点。卸载时释放 WebGL 资源。画布只在挂载和真实 `resize` 时读取 CSS 尺寸并更新设备像素尺寸，不得在每个动画帧强制布局。Canvas 的 `data-astral-renderer`、`data-astral-quality`、`data-astral-star-count` 和 `data-astral-pixel-ratio` 固定暴露当前只读渲染档，供真实 Web Inspector 验收。

## 后果

- 召唤、图片失败重试和结果舞台共同渲染同一个 `GachaAstralBackdrop` 程序化背景，不再请求或显示月夜庭院图片；召唤 Canvas 只在该基础星域上叠加动态飞行和揭晓。
- 开盒结果、请求数量、图片 `decode()` 门控、稀有度公开时点、触觉、声音和结果弹窗仍由 ADR-021 裁决；本 ADR 不改变任何数据库、API、RPC、资产或概率规则。
- 特效模块继续位于动态开盒表现 chunk，首屏同步闭包不新增图形依赖或效果资源。真实验收必须在 iPhone Telegram 与 Safari Web Inspector 中检查 WebGL2、渲染档数据属性、Canvas 设备尺寸、单次 `gacha.open`、4 秒门控、同一 Canvas、星域连续性、帧间隔和控制台错误。
