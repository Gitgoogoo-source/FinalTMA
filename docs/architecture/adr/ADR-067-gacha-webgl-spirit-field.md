# ADR-067：开盒 WebGL 灵绸粒子场渲染边界

## 决定

开盒动态主体固定由按需加载的 `GachaSpiritFieldRenderer.ts` 独立渲染，不引入 Three.js、PixiJS、Lottie、视频、透明序列帧、粒子贴图或第三方特效运行时。该文件只接收画布尺寸、`3300ms + 700ms` 表现进度和最后阶段已经允许公开的稀有度颜色，不读取盲盒档次、operation、价格、资格、保底、结果内容、宠物图片或任何服务端数据。

主路径使用 WebGL2 和内置 GLSL ES 3.00 着色器，分成三个固定绘制程序：全屏场程序在保留唯一结果底图可辨识度的前提下绘制最大不透明度 `0.34` 的中央深灰蓝渐隐衬底、暖金吸力核、水面涟漪、垂直尾迹和揭晓冲击波；灵绸程序用六条同向旋转、非对称 S 形的确定性流场曲线和受设备档控制的动态网格绘制半透明纤维、断续噪声、象牙白细外缘和暖金主体内光，不能形成对称沙漏、蝴蝶或三个封闭实体叶片；粒子程序让确定性种子的光尘、星芒和菱形碎片沿同一曲线、法线离散和速度场运动，并在揭晓时从核心径向甩出。着色器、几何和粒子数据全部随开盒表现 chunk 加载，不进入首屏同步闭包，也不产生网络资源请求；默认开盒页完成首屏就绪后只通过动态加载边界提前准备该 chunk。

普通设备固定使用 `720` 个 WebGL 粒子、每条灵绸 `72` 段并将设备像素比封顶 `1.25`；`hardwareConcurrency <= 4` 固定使用 `420` 个粒子、每条灵绸 `56` 段、关闭多重采样抗锯齿并将设备像素比封顶 `1`。系统启用减少动态效果时只绘制一次 `3300ms` 临界帧，保留六股灵绸和 `120` 个静态光尘，不继续请求动画帧、不播放稀有度爆发。WebGL2 创建失败时，同一个 Canvas 使用无实体封闭面的 Canvas 2D 同构降级：普通、四核及以下和减少动态效果分别使用 `200 / 144 / 48` 个光尘，普通与四核及以下灵绸分别使用 `52 / 40` 段；WebGL 程序已经创建后如果运行期上下文丢失，既有 4 秒门控仍继续进入权威结果，不重试业务请求或推测结果。

渲染器的 React 包装只在表现组件挂载时创建一次 WebGL context、program、buffer 和 vertex array；进入揭晓阶段时只更新同一实例的时间轴与稀有度颜色，以 `3300ms + 当前揭晓时间` 继续同一确定性粒子相位，不得因 React 状态切换重新编译着色器、重建缓冲区或让粒子跳回起点。卸载时释放 WebGL buffer、vertex array 和 program。画布只在挂载和真实 `resize` 时读取 CSS 尺寸并更新设备像素尺寸，不得在每一个动画帧调用 `getBoundingClientRect()`；Canvas 的 `data-spirit-renderer`、`data-spirit-quality`、`data-spirit-particle-count`、`data-spirit-ribbon-segments` 和 `data-spirit-pixel-ratio` 固定暴露当前只读渲染档，供真实 Web Inspector 验收。

## 后果

- 视觉参考图只用于确定六股纵向纤维流、核心亮度、粒子密度和水面落点，不复制进静态资源，也不参与运行时帧合成。
- 开盒结果、请求数量、图片 `decode()` 门控、稀有度公开时点、触觉、声音和结果弹窗仍由 ADR-021 裁决；本 ADR 不改变任何数据库、API、RPC、资产或概率规则。
- 静态门禁必须确认特效模块仍位于动态开盒表现 chunk，首屏同步闭包不新增第三方图形库；默认开盒页首屏就绪后的准备只能动态下载该 chunk 和唯一月夜底图。真实验收必须在 iPhone Telegram 与 Safari Web Inspector 中检查 WebGL2 上下文、渲染档数据属性、Canvas 设备尺寸、单次 `gacha.open`、4 秒门控、背景连续性、帧间隔和控制台错误。
