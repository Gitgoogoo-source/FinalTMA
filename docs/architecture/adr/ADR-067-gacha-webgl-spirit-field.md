# ADR-067：开盒 WebGL 灵契星轨渲染边界

## 决定

开盒动态主体固定由按需加载的 `GachaAstralFieldRenderer.ts` 独立渲染，不引入 Three.js、PixiJS、Lottie、视频、透明序列帧、粒子贴图或第三方特效运行时。视觉节奏采用已经由用户裁决的“点火、星轨穿越、真实稀有度变色、撞入光门、结果稳定”结构，但所有 GLSL、几何、颜色、文案和合成音均为本项目原创，不复制参考游戏的素材、角色、图标、界面或具体镜头。

主路径使用 WebGL2 和内置 GLSL ES 3.00 着色器，分为全屏星域和星轨几何两个程序。全屏星域绘制深蓝黑远空、青蓝与淡紫星云、中央远端光门、主灵光和揭晓冲击环；星轨几何使用确定性三维种子向中央消失点投影为透视光迹，随蓄能进度提高相机速度、长度和亮度。前 `3300ms` 仅使用中性冰蓝、象牙白和淡紫，不读取盲盒档次，也不泄露稀有度；最后 `700ms` 才使用已允许公开的真实稀有度颜色改变主灵光、星轨边缘、光门和冲击环。到达临界门控而结果或图片未准备完成时，星轨冻结在中性光门前，不循环、不继续飞行。

普通设备固定使用 `520` 条 WebGL 星轨并将设备像素比封顶 `1.25`；`hardwareConcurrency <= 4` 固定使用 `320` 条星轨、关闭多重采样抗锯齿并将设备像素比封顶 `1`。系统启用减少动态效果时只绘制一次由 `96` 个静态星点、光门和主灵光组成的临界帧，不继续请求动画帧、不播放稀有度爆发。WebGL2 创建失败时，同一个 Canvas 使用 Canvas 2D 同构降级：普通、四核及以下和减少动态效果分别使用 `180 / 120 / 48` 条星轨或星点。WebGL 程序已经创建后如果运行期上下文丢失，既有 4 秒门控仍继续进入权威结果，不重试业务请求或推测结果。

渲染器的 React 包装只在表现组件挂载时创建一次 WebGL context、program、buffer 和 vertex array；进入揭晓阶段时只更新同一实例的时间轴与稀有度颜色，以 `3300ms + 当前揭晓时间` 继续同一确定性星轨相位，不得因 React 状态切换重新编译着色器、重建缓冲区或让星轨跳回起点。卸载时释放 WebGL 资源。画布只在挂载和真实 `resize` 时读取 CSS 尺寸并更新设备像素尺寸，不得在每个动画帧强制布局。Canvas 的 `data-astral-renderer`、`data-astral-quality`、`data-astral-star-count` 和 `data-astral-pixel-ratio` 固定暴露当前只读渲染档，供真实 Web Inspector 验收。

## 后果

- 召唤、图片失败重试和结果舞台共同渲染同一个 `GachaAstralBackdrop` 程序化背景，不再请求或显示月夜庭院图片；召唤 Canvas 只在该基础星域上叠加动态飞行和揭晓。
- 开盒结果、请求数量、图片 `decode()` 门控、稀有度公开时点、触觉、声音和结果弹窗仍由 ADR-021 裁决；本 ADR 不改变任何数据库、API、RPC、资产或概率规则。
- 特效模块继续位于动态开盒表现 chunk，首屏同步闭包不新增图形依赖或效果资源。真实验收必须在 iPhone Telegram 与 Safari Web Inspector 中检查 WebGL2、渲染档数据属性、Canvas 设备尺寸、单次 `gacha.open`、4 秒门控、同一 Canvas、星域连续性、帧间隔和控制台错误。
