# ADR-072：进化随机失败结果真实轮廓剪影

- 状态：已接受
- 日期：2026-08-15

## 背景

进化随机失败是已完成结算的真实结果。旧界面在暗色光点动画后按近似成功态的主视觉尺寸重新展示原藏品彩色详情图，失败与成功的视觉差异不足，也使失败结果的藏品大图抢占结算信息的注意力。用户已明确裁决，随机失败后不再展示该彩色大图，改为使用本次原藏品的真实轮廓黑影，不使用全藏品共用的通用图形。

## 决策

只对 `inventory.evolve` 已结算且 `success_count = 0` 的随机失败结果应用剪影表现。界面继续把服务端完整结果中 `source.image_detail_url` 的正式 768×768 WebP 交给共享 `CatalogImage`，保留公开桶 URL 校验、解码门控、有限重试与 Vercel 内置剪影回退；不新增结果字段、图片接口、静态藏品资源或前端直连。

随机失败舞台使用独立的 `evolution-stage-pet--failure-silhouette` 状态。该状态把原藏品容器限制为舞台宽度的 `62%` 和高度的 `36%`，内部正式图像固定去色并压为纯黑像素，只保留一层克制的暖色轮廓光与黑色投影，使黑影在日蚀舞台的暗色中心仍可辨识；不恢复宠物的内部颜色、纹理或细节。短视口中剪影高度缩小为 `32%`，不与底部结果卡重叠。进入动画只执行一次轻微下落和收束；当用户要求减少动效时直接显示最终剪影。

结果卡继续展示“进化失败”、“藏品保持原形态”、原藏品名称、未获得目标藏品的说明、真实结算详情与“知道了”。结果说明固定改为“只留下原藏品的黑色轮廓，本次没有获得目标藏品”，使文案与画面一致。

“进化中断”表示结果仍未确定，“进化未执行”表示前置拒绝；这两类状态继续展示原藏品彩色详情图，不使用失败剪影，避免把未知或未结算状态伪装成随机失败。成功态的目标藏品大图、彩带、NEW 与图鉴动作完全不变。

## 不变量

- 剪影必须来自该次结果中的原藏品真实详情图轮廓；禁止以通用藏品图形替代可用的真实轮廓。
- 黑影不得显示原图的内部色彩、纹理或细节；光晕只用于勾边，不能把藏品恢复成半透明彩色大图。
- 剪影、暗色光点和结果卡不得重叠遮挡，结果卡的关闭、结算详情和“知道了”必须始终可见可操作。
- 这项表现变更不改变进化提交、成功率、保底、材料、Gems、图鉴、任务、幂等、结果回执或恢复规则。

## 验收

静态影响域必须通过 Prettier、ESLint、Web TypeScript、架构检查和生产构建。同一部署 SHA 必须在真实 iPhone Telegram Mini App 中完成一次全部随机失败结算，并通过 Safari Web Inspector 确认：失败结果只有原藏品真实轮廓的小尺寸黑影，无彩色大图；轮廓在日蚀暗部可辨；黑影、暗色光点与结果卡不重叠；较短稳定视口与减少动效模式不裁切剪影或结果操作。另行触发“进化中断”或“进化未执行”时，必须仍为原藏品彩色图且不得出现失败剪影。普通浏览器响应式预览、截图或静态构建不能替代该真机验收。
