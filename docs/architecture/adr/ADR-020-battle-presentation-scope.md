# ADR-020：Battle 对战视觉作用域与首页像素动画

## 状态

已接受。

## 背景

Battle 需要在实际对局中呈现早期 GBA 宠物对战游戏的画面组织方式，同时必须保持项目既有应用外壳和非对局页面的设计一致性。视觉变化不得改变 Battle 功能、资产、接口或服务端裁决。

## 裁决

红宝石式 GBA 对战视觉只作用于 `battle` 中部实际战场和行内换宠区域。战场使用项目正式资源 `/assets/battle/ui/ruby-arena-field.webp` 与正式宠物图片，固定为对手状态左上、对手宠物右上、己方宠物左下、己方状态右下；技能使用两列指令卡，主动换宠使用整行按钮。需要换宠反击时先选存活宠物，本人战场立即以本地预览显示该宠物的大图、名称、生命和槽位高亮，再展示该宠物的真实技能；该预览不发送请求且不向对手展示，对手只消费服务端成功结算后的权威换入结果。点击攻击后可以立即播放施法、移动与弹道；命中、未命中、受击、伤害、生命变化和死亡只消费服务端动作事件。

权威快照立即控制当前行动方、倒计时、按钮和合法选项；表现状态只按动作 sequence 串行更新战场。上一动作尚未播完时，新动作进入队尾，动画层不得拦截指针。终局资产与库存立即回正，结果覆盖层等待表现队列清空后显示；reduced-motion 仍按相同顺序无动画应用事件。

应用全局顶部资产栏和共享底部导航继续使用项目原有样式；除既有 `lobby_countdown` 专用全屏锁定状态仍按原规则覆盖外，其余状态均保持展示。`home`、`team_select`、`preparing_share`、`waiting`、`accept`、`lobby` 与 `result` 全部保留项目原有设计，不继承对局战场的颜色、字体、边框、背景或按钮样式。

Battle 首页继续使用原有约 3 秒循环双怪兽像素动画。该动画使用既有 React 内联 SVG 和 CSS 关键帧，不读取真实战斗状态，不表达真实攻击、伤害或胜负；对辅助技术隐藏。启用 `prefers-reduced-motion` 时停止循环与闪烁并保留静态双怪兽画面。

不得复制或引入 Pokémon 图片、精灵、图标、音频、文字商标、PokeAPI 或第三方战斗代码。

## 结果

Battle 的八种页面状态、队伍选择、金额、权限、幂等、库存占用、错误处理、数据库裁决和 API 契约保持统一。实际对局拥有独立的 GBA 战场表现，其他页面及全局壳层不会被 Battle 场景样式覆盖。
