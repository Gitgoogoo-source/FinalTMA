# ADR-009：开盒页运行期视图状态

## 决定

开盒页的档次与页面滚动位置只保存在 Web 运行内存中，以当前已确认会话的 generation 隔离。当前会话首次进入开盒页且没有充值恢复档次或已保留页面状态时，默认选中普通、稀有、传说三档中的第 1 档普通盲盒。页面首次访问后在该登录会话内保持挂载，主导航切换只隐藏页面并保存滚动位置，不卸载或重新创建开盒页；用户离开后返回时继续显示离开前的档次，不重置为首次默认档次。会话敏感状态清理时清空全部开盒页记忆；Mini App 重新启动不会恢复这份内存状态，也不使用 `localStorage`、`sessionStorage` 或服务端数据保存视图记忆。

普通、稀有和传说三档主展示图在开盒页取得档次数据后立即以独立图片节点并行加载，并在页面存续期间保持挂载。档次切换只改变三张主展示图的可见状态，未选中的主展示图停止浮动动画但继续保留已加载资源；不得通过档次 `key` 销毁并重新创建当前主图。每档图片可用状态独立记录，开盒按钮只依据当前选中档次的图片状态启用。缩略图仍独立承担档次选择展示，不作为主展示图的预加载或解码保证。

开盒页首次挂载或重新激活时，只接受当前 TMA 运行内存绑定的充值订单生成的开盒恢复 query 参数覆盖普通页面记忆；历史支付订单、历史 operation 和外部构造的旧 `resume` 参数都没有展示资格。隐藏期间只保留最后一次属于开盒页的参数，不响应其他页面地址。页面切换不强制重新读取 `gacha.bootstrap`。普通查询或后台回正即使发现已有免费稀有资格也不覆盖用户当前选择；只有当前运行期明确领取免费稀有资格后发出的权益事件，或合法页内导航参数，才将档次切换为稀有盲盒。当前运行期充值恢复的单抽或十连意图只打开底部确认弹窗，不触发开盒请求；关闭弹窗只保留对应档次并移除恢复 query，确认按钮才提交一次新的 `gacha.open`。刷新、关闭、重新认证或 Mini App 重新启动会清除内存订单绑定，因此不恢复确认弹窗。

该确认弹窗属于当前运行期付款意图恢复表现，余额不足时即预取其独立模块，内存绑定订单与恢复参数同时匹配时才动态加载；弹窗复用通用 `AppModal` 的焦点圈闭、Escape 关闭、背景 `inert`、滚动锁定和焦点恢复能力，但 `AppModal` 不得进入默认开盒首屏的同步闭包。动态边界接受 ADR-040、ADR-046 的体积和禁止模块门禁。跨运行期边界由 [ADR-061](ADR-061-gacha-topup-continuation-runtime-boundary.md) 固定。

价格、概率、保底、免费资格和开盒结果始终来自服务端响应。“可能获得”的固定代表图是前端版本化静态展示资源，稀有度概率仍使用 `gacha.bootstrap` 的当前档次规则；代表图不参与候选集、随机或结果决定。运行期视图状态不参与资产、资格、扣款、随机结果或业务成功判断。

结果弹窗使用服务端已确认的付费方式、最终稀有度、保底目标和固定保底触发标记解释保底变化。付费结果达到目标且未标记固定保底触发时，界面明确标记为自然命中重置；免费结果不生成任何重置说明。该说明只解释服务端已经裁决的结果，不参与保底累计、重置或最终进度计算。

召唤动画和结果弹窗同样只存在于本次前台运行期。结果终态到达时数据库已经完成全部业务结算，弹窗按钮不保存确认事实：“确定”和“去藏品查看”不发送请求，“再开一次”只允许创建新的 `gacha.open`。页面隐藏、Telegram `deactivated`、`pagehide`、刷新、关闭、重新认证或 Mini App 重新启动时清除全部开盒 operation 展示；再次进入固定显示开盒首页并读取最新权威状态，不从服务端 operation 记录恢复旧召唤结果。
