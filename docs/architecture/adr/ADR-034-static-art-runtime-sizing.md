# ADR-034：Vercel 静态美术运行时尺寸与 PNG 编码

## 状态

已接受。

## 决定

非宠物静态美术继续随 Vercel 版本发布。`apps/web/public/assets` 只保留当前运行时实际引用的交付文件，不把已经退出界面且没有契约、清单或运行时代码引用的旧方案图片继续复制到部署产物。历史 Git 提交保留被删除文件；设计资料中的当前运行时尺寸、Alpha 边界和校验值必须同步，已经被明确记录为历史方案的视觉过程不因运行时清理而删除。

运行时图片尺寸按当前全部响应式样式中的最大 CSS 展示盒、目标屏幕像素倍率、动画缩放和构图留白逐张确定，不使用统一尺寸或统一缩放比例。固定小图标覆盖 4 个源像素对应 1 个 CSS 像素；较大插画覆盖 3 倍屏幕像素并保留 20% 缩放余量。源图宽高比、构图范围和透明边缘保持不变，不裁切有效像素。

本次六张 PNG 的唯一运行时规格为：

| 路径                                 |                                    最大当前展示盒 | 运行时尺寸 | 像素格式       |
| ------------------------------------ | ------------------------------------------------: | ---------: | -------------- |
| `/assets/vip/vip-daily-fgems.png`    |                                      28×28 CSS px |    112×112 | 8-bit RGBA PNG |
| `/assets/vip/vip-daily-gift.png`     |                                      28×28 CSS px |    112×112 | 8-bit RGBA PNG |
| `/assets/vip/daily-fgems.png`        |                                      44×44 CSS px |    176×176 | 8-bit RGBA PNG |
| `/assets/vip/daily-rare-egg.png`     |                                      44×44 CSS px |    176×176 | 8-bit RGBA PNG |
| `/assets/tasks/checkin-fgems-v2.png` |                                      54×54 CSS px |    216×216 | 8-bit RGBA PNG |
| `/assets/tasks/invite-gifts.png`     | 约 200×160 CSS px 的 `object-fit: contain` 展示盒 |    768×576 | 8-bit RGB PNG  |

图片使用 Sharp 的 Lanczos3 核从当前正式运行时文件确定性缩放；PNG 使用压缩级别 9 和自适应过滤，继续保留真彩通道，不使用调色板量化、颜色降级、有损格式转换、裁切或锐化。现有 URL、React 引用和产品规定的透明 PNG 交付格式保持不变。

## 一致性与失败处理

处理前必须确认删除目标没有运行时代码、样式、契约、生成清单或受控发布工具引用；只出现在历史设计记录中的旧文件可以退出公开运行时目录，历史记录正文保持原样。任一目标出现新引用时必须停止删除并重新裁决，不能通过删除引用来通过检查。

图片替换必须先在临时目录完成，并在覆盖正式文件前逐张验证 MIME、宽高、通道数和可解码性。任一输出失败时不得覆盖该源文件。六张图片继续使用原 URL，因此一次构建内不会出现代码与资源路径不一致；部署后必须复核正式 URL 的新尺寸、字节数和缓存响应，不得把本地文件或构建成功描述为真实 Telegram 视觉验收。

`apps/web/dist` 与 `.vercel/output` 是生成结果，不作为图片事实来源，也不手工压缩。发布构建必须从 `apps/web/public/assets` 重新生成并通过现有资源、架构、类型、格式和构建检查。

## 验证

静态门禁固定验证六张 PNG 的路径、PNG MIME、精确尺寸、原有 RGB/RGBA 通道类型和文件体积下降；全项目扫描确认被清理的十个 URL 不存在运行时引用，且剩余 `/assets/` 引用均能解析到文件。随后执行既有全量静态检查和生产构建。

真实开发环境部署后，必须在 Telegram Mini App 中复核 VIP 横幅、顶部每日权益、七日签到和邀请页的清晰度、透明边缘、构图和动画状态。任何一处出现肉眼可见的锯齿、色带、透明黑边、裁切或模糊，都必须恢复该资源的上一份 Git 内容并提高对应运行时尺寸，不能通过 CSS 锐化掩盖资源问题。
