# ADR-071：市场出售页首屏自适应布局

- 状态：已接受
- 日期：2026-08-15

## 背景

出售页工作区按照 Telegram 稳定视口、顶部内容安全区、设备底部安全区、全局资产栏和底部导航计算可用高度。工作区原先把最后的“出售数量和结算确认区”限制为 `clamp(104px, 29%, 160px)`，再通过 `align-content: space-between` 分配未使用高度。新增固定展示的上架额度行后，表单内容的最小高度已经超过 `160px`，但网格上限没有同步变化。通用 `Card` 的 `overflow: hidden` 因而裁掉越过表单边界的确认按钮，按钮的实际底边还进入了底部导航区域。

真实 iPhone Telegram 的故障现场为 `414 × 896 CSS px`：出售表单边界为 `621–781px`，确认按钮边界为 `752–796px`，按钮向下越过表单 `15px`；底部导航从 `794px` 开始，按钮同时与导航重叠 `2px`。这证明缺陷来自固定表单上限与新增内容不一致，不是图片加载、设备 Home Indicator 或 Telegram 安全区变量失效。

## 决策

出售工作区继续使用 Telegram `viewportStableHeight`、当前动态视口、设备安全区、内容安全区和共享壳层尺寸计算唯一可用高度，不增加设备型号判断，也不写死某一台手机的屏幕高度。

工作区四行改为内容下限优先的弹性网格：选中藏品、双行缩略图和价格摘要使用可压缩的 `31fr / 21.5fr / 12fr`；最后的出售表单使用 `minmax(min-content, 1fr)`，先完整保留数量、预计结算、上架额度和 `44px` 确认按钮，再把剩余高度按前三行比例分配。网格只使用既有响应式 `gap`，不再用 `space-between` 把空余高度重复加入三处行间距。出售表单使用自动高度并向网格贡献真实最小内容高度，不再以 `height: 100%` 和 `min-height: 0` 隐藏内容需求。

这项布局裁决不改变出售页信息顺序、缩略图双行横向滚动、底部导航几何、价格、数量、手续费、配额、按钮状态、上架请求或数据库裁决。

## 不变量

- 支持的 iOS 与 Android Telegram 竖屏中，出售页全部区域和全部功能按钮必须在稳定首屏内同时可见，页面无需纵向滚动。
- 确认出售按钮保持至少 `44px` 高，完整位于出售表单内部，并位于固定底部导航上方；卡片裁切边界和底部导航均不得覆盖按钮。
- 视口高度、安全区或 Telegram 内容安全区变化时，只通过同一可用高度公式与弹性网格重新分配空间，不增加设备型号、固定截图高度或页面级导航补丁。
- 出售表单新增或移除固定可见业务行时，网格必须读取其真实最小内容高度，禁止恢复独立的固定高度上限。

## 验收

静态影响域必须通过 Prettier、ESLint、Web TypeScript、架构检查和生产构建。相同部署 SHA 必须在真实 Telegram iOS 与 Android 竖屏中覆盖至少一组不同视口高度，并在 Safari Web Inspector 或对应平台调试器中同时核对稳定视口、安全区、工作区、出售表单、确认按钮和底部导航边界：表单不得发生内容溢出，按钮边界必须完全包含在表单边界内且底边小于导航顶边；页面内容滚动位置保持为首屏。静态构建、普通浏览器响应式预览或单一设备截图不能替代跨设备真实 Telegram 验收。
