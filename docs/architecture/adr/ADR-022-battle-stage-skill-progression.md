# ADR-022：Battle 阶段技能成长与无隐藏技能契约

## 状态

已接受；技能有效威力的固化与跨稀有度约束由 ADR-095 补充并部分取代本文原 power 语义。

## 决定

`battle-v1` 为每条进化链保留四技能候选池。产品数据生成器按 `(数值槽位基础 power 升序, 候选池原始位置升序)` 生成唯一成长顺序，并在构建期依据 `catalog.templates.stage` 为 210 个模板固化技能 ID 与 ADR-095 定义的模板有效威力：1 阶 2 个、2 阶 3 个、3 阶 4 个。技能位置在每个模板内连续编号为 `1..N`，同链低阶段技能 ID 与有效威力数组必须同时是高阶段数组的前缀。运行时不按阶段、稀有度或客户端输入重新推导技能。

`battle.template_configs` 与房间不可变快照 `battle.team_members` 继续使用最大四列结构。技能 1、2 必填；技能 3 仅 2/3 阶非空；技能 4 仅 3 阶非空。数据库约束强制技能数等于 `stage + 1`、空值只位于连续尾部、非空技能互不重复。该固定上限保持 `skill_position` 玩家输入为 `1..4`；数据库把位置映射到快照，未拥有位置返回 `BATTLE_ACTION_INVALID` 且不写 action。

数据库读模型按位置聚合非空技能，队伍选项与己方队伍 DTO 只返回长度 2—4 的真实技能数组。API、OpenAPI 和 Web 不定义或渲染锁定、隐藏、未来解锁或 `null` 技能；三技能操作区只调整现有按钮布局。对手技能隐私保持 ADR-014 的 viewer-specific 边界。

模板实际技能不保证包含 100% 命中项，生成器和数据库完整性门禁校验阶段数量、基础 power 形成的技能顺序、有效威力非降序、跨稀有度严格递增、同链 ID/有效威力前缀、元素和唯一性，不为命中率重排或补充技能。自动行动固定使用快照中实际拥有的技能位置 1，不按命中率、威力或其他技能数值重新选择。

本变更是应用契约与数据库数据的双向不兼容切换。旧契约要求每个模板恰好返回四个技能，新数据库对 1/2 阶只返回 2/3 个；新契约要求技能数严格等于 `stage + 1`，旧数据库对 1/2 阶仍返回四个。数据库保留四个固定列只表示存储上限，不表示四技能响应兼容。禁止通过放宽契约、运行时按阶段裁剪旧数据、补回未拥有技能或增加旧响应分支制造过渡兼容；真实开发环境必须按 ADR-001 把完整提交推送到 `main` 自动部署，并从同一提交重建数据库，不暂停 Vercel Project。

## 结果

数据库仍是技能归属的最终事实来源，房间创建时复制的技能快照不受后续产品数据变化影响。Catalog v1 的 70 条链、210 个模板和 release checksum 不改变；`battle-v1` 的生成 JSON、产品数据 SQL、数据库规则 checksum 与接口契约同步更新。发布过程不声称新旧应用与数据库互相兼容；唯一允许的短暂不匹配状态位于尚未开始验收且 Telegram 业务入口与调度保持关闭的真实开发切换过程内，Vercel Project 本身保持启用。
