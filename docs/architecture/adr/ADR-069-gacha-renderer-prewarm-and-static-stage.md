# ADR-069：开盒渲染器预热复用与静态星域

## 决定

默认开盒页首屏事实就绪并完成 `gacha.open` 表现模块加载后，模块在浏览器空闲回调中创建一张脱离文档流的真实 Canvas，按当前 `hardwareConcurrency` 与减少动态效果设置完成 WebGL2 或 Canvas 2D context、program、buffer、vertex array 和一帧中性绘制，并把这些资源保留为全局单实例池。WebGL 路径必须在该空闲任务内调用一次 `finish()`，等待预热绘制和延迟 GPU 工作真实完成后才能把实例标记为 `warm`，禁止只把 draw call 排入驱动队列就宣称已预热。开盒表现挂载时直接把这张 Canvas 放入演出内的既有绝对定位宿主，由宿主的实际尺寸执行一次 drawing buffer 对齐和中性绘制，并在 WebGL 路径再次以 `finish()` 完成该全尺寸帧；随后最多使用 6 个静态合成帧等待 iOS WebKit 全尺寸层稳定，并在连续两帧间隔不超过 `50ms` 后发布 `data-astral-stage="ready"` 才启动 4 秒呼吸时间轴，尺寸对齐期间只显示既有静态深空舞台，不得让呼吸进度先行跳过；表现卸载时只把 Canvas 脱离宿主并回收到池中，禁止创建或显隐一张独立的全屏根层 surface。后续同会话开盒继续复用同一 Canvas 与 GPU 资源；质量档发生变化时释放旧实例并按新档重建，页面 `pagehide` 时释放池内资源。池被占用或空闲预热尚未执行时允许创建唯一的即时实例，但不得并行共享一个 WebGL context。

同一表现模块加载完成后，所有设备必须按 [ADR-082](ADR-082-gacha-unified-electronic-heartbeat-sound.md) 在空闲回调中创建可复用的开场 Web Audio 双拍电子心跳自动化曲线与短有色噪声纹理：曲线每次最多计算 `256` 个时间点，纹理每次最多计算 `2048` 个采样，然后重新排队。用户点击时若准备尚未完成，必须在可见动画开始前完成剩余内容并解锁 `AudioContext`；舞台发布 `data-astral-stage="ready"` 的同一回调只创建轻量音频节点并应用完整曲线，不得因核心数、准备时序或上下文仍在恢复而省略音效。四核及以下设备仍不触发开场、服务端成功或揭晓阶段的 Telegram `HapticFeedback`，但必须与其他支持 Web Audio 的设备一样播放统一的电子心跳和揭晓音效；核心数只影响 ADR-067 的 Canvas/WebGL 质量上限。音频能力不存在、浏览器明确拒绝解锁或系统输出静音时的静默降级不改变动画计时、业务请求或结果，结果舞台后续用户交互仍保留普通控件反馈。

动画挂载后的前三轮中性呼吸固定独占前 `1840ms`；即使服务端成功结果已经返回，也不得在此之前准备结果图片或挂载结果 DOM。`1840ms` 到达后只允许用脱离 DOM 的 `Image` 对单抽详情图或十连全部缩略图执行公开 URL 校验、读取和异步 `decode()`，不得创建结果布局、背景、光环、按钮、图片绘制节点或新的合成层。完整 `GachaResultDialog` 固定等到 4 秒中性呼吸结束、黑洞进入应当静止的最大临界帧后才挂载，并沿用预取后的浏览器图片缓存完成正式 `CatalogImage.decode()`、最终尺寸绘制和纹理上传；这些准备未完成时继续停在最大中性临界帧，不缩短呼吸、不跳过图片门控，也不改变服务端结算。四核及以下路径把 WebGL 与 Canvas 2D 的像素比封顶 `0.75`，保留相同粒子数、呼吸次数、时间轴与视觉尺寸，只减少不可感知的内部采样负担。

汇聚阶段的 CSS `GachaAstralBackdrop` 固定为静态深黑渐变、静态星尘和无滤镜星云，不运行全屏 `blur`、`mix-blend-mode`、星尘呼吸、星云位移或第二套全屏黑洞呼吸。前 `4000ms` 的 13 次黑洞呼吸、事件视界、吸积流与螺旋粒子只由 ADR-067 的同一个 WebGL2/Canvas 渲染器驱动；最后 `700ms` 揭晓的金光、冲击环、触觉与音效保持 ADR-021 的现有裁决。移除重复 CSS 动态层不得改变呼吸周期、黑洞尺寸、粒子上限、颜色、图片门控、结果排序、概率、扣款、资格、保底、藏品或任何服务端结算。

Canvas 固定暴露 `data-astral-startup="warm|cold"`，并继续暴露 ADR-067 的渲染器、质量档、粒子数、呼吸周期和像素比属性。真实验收必须在关闭 Safari Web Inspector 的 iPhone Telegram 中检查完整呼吸肉眼无明显停顿；另开一轮 Inspector 只核对这些数据属性和结构，不以开启 Inspector 后的 `requestAnimationFrame` 帧间隔裁决产品流畅度。首屏静态检查、构建通过或部署 READY 都不能替代真机结论。

## 后果

- 动态模块仍按需加载，首屏同步闭包不引入 WebGL 代码、第三方运行时、图片、视频或序列帧；预热只在开盒页事实就绪后执行。
- 同一会话首次和重复开盒都不再把 shader 编译、GPU 程序资源初始化、驱动延迟提交、音频噪声逐样本生成与首轮呼吸争用同一个可见帧，也不再为复用 GPU 资源而显隐独立的全屏合成 surface；四核及以下设备也不再由首次音频管线建立、定时振荡器启动或 Telegram 原生触觉桥接打断可见帧。Canvas 在演出既有宿主中只承担黑洞和粒子，静态深空背景由低成本 CSS 舞台承担。
- 程序化星域的视觉身份保持不变，但汇聚阶段只有一套动态黑洞时间轴，避免 WebGL 与 CSS 重复绘制全屏呼吸效果。
- 服务端结果返回、图片准备和完整结果合成树创建都不得打断 4 秒呼吸；较慢图片或结果舞台预绘只延长既有中性临界停留，不产生错误结果或重复结算。
