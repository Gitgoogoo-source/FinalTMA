# ADR-082：开盒统一电子心跳音效

## 状态

已采纳，取代 [ADR-081](ADR-081-gacha-warm-gold-convergence-sound.md) 的暖金奇幻汇聚音色，以及 ADR-021 中按真实稀有度增强揭晓音效的旧规则。

## 裁决

三档盲盒、单抽、十连和普通、稀有、史诗、传说、神话五种结果固定共用同一套 `4700ms` 现场合成音效。音频参数不得读取盲盒档次、结果稀有度、抽取数量、保底状态或宠物内容；结果稀有度仍可按 ADR-021 控制最后 `700ms` 的画面色调和既有 Telegram 触觉强度，但不得改变声音。前后两段均不读取音频文件、不引入第三方音频运行时、不发起网络请求，也不生成或缓存多份成品音效。

前 `4000ms` 固定使用神秘、紧张但不恐怖的双拍电子心跳。全部 13 轮继续共用 ADR-067 的周期 `800 / 580 / 460 / 380 / 330 / 290 / 260 / 230 / 200 / 170 / 130 / 100 / 70ms`；每轮在相同相位依次产生一次较强主心跳和一次较弱副心跳，随黑洞呼吸逐轮加速，最后短周期自然汇成临界连拍。主副心跳的低频冲击、可在手机扬声器辨识的中低频电子躯干、短促噪声瞬态和逐步增强的高频电流共同使用同一条时间轴。前四秒不得形成旋律、语音、恐怖生物质感、街机鼓点、随机音色、独立揭晓撞击或稀有度暗示。

最后 `700ms` 固定由前 `300ms` 完全静音和后 `400ms` 同一套实体扭蛋胶囊“啵啪”弹开声组成。揭晓开始后的 `0–300ms` 不得启动揭晓音源或产生任何可听输出；到 `300ms` 后，同一固定种子纹理从固定 `0.271s` 偏移开始，先经 `480Hz` 带通形成一次圆润、短促而不低沉的气压释放“啵”，再在揭晓时间轴 `318ms` 经 `1750Hz` 带通和 `3400Hz` 高通同时形成一次紧接其后的干净塑料壳回弹“啪”。两次瞬态必须连成同一次胶囊盖被顶开的动作，不得听成两次开盒；可听主体在约 `105ms` 内收束，纹理源在 `520ms` 停止，最后约 `180ms` 不再保留人工尾音。揭晓段不得创建振荡器，不得出现电音、铃声、机械弹扣、裂纹扩展、玻璃碎裂、爆炸、固定音高、旋律、蜂鸣器、低频重砸、延迟或长混响。全部纹理偏移、滤波、包络、增益和持续时间对所有盲盒与结果完全相同，不得按稀有度改变。胶囊弹开声只在 ADR-021 的真实结果与图片门控放行后播放一次，不能提前泄露结果。

## 实现

表现模块空闲准备时，继续以 `2001` 个时间点生成两条振荡器频率、两条振荡器增益、两条纹理滤波频率和两条纹理增益，共八条 `AudioParam` 自动化曲线；每个空闲回调最多计算 `256` 点。主副心跳包络由纯函数 `gachaRitualHeartbeatAt()` 生成，使用同一组 13 段周期；短周期对包络宽度作有界扩展，避免单采样点击，但不得改变每轮一强一弱两次心跳的顺序。

系统继续以固定种子分块生成一份 `16384` 采样、`12000Hz` 的可循环有色噪声纹理，每个空闲回调最多计算 `2048` 个采样。该纹理不是成品音频，不包含盲盒或结果差异；前四秒继续把它用于瞬态带通和高频电流高通支路，最后 `700ms` 只在揭晓时间轴到达 `300ms` 后从固定 `0.271s` 偏移读取同一纹理的 `220ms`，不得另行生成或下载揭晓素材。玩家点击时若准备尚未完成，必须在可见演出前完成剩余曲线与纹理并解锁 `AudioContext`；舞台发布 `data-astral-stage="ready"` 的同一回调只创建前四秒所需的两条实时振荡器、一条纹理源、滤波、增益和压缩节点，前段主增益必须在精确的 `4.000s` 边界置零，即使其音源节点为安全收尾而继续存活也不得向揭晓静音段输出。最后 `700ms` 的揭晓节点只创建一条延迟到 `300ms` 启动并在 `520ms` 停止的纹理源，以及 `480Hz` 气压带通、`1750Hz` 壳体带通和 `3400Hz` 壳边高通三条胶囊弹开支路，并进入一条阈值 `-20dB`、比例 `3:1`、攻击 `1ms`、释放 `70ms` 的统一压缩节点；不得创建揭晓振荡器、延迟或混响节点。

揭晓调用固定为无稀有度参数的 `playGachaRitualReveal()`。揭晓时不得调用随机数、生成新纹理或读取音频文件；所有轮次使用同一 `300ms` 静音边界、同一固定纹理偏移、同一三条胶囊弹开滤波支路和同一增益包络，保证同一设备和音频能力下的合成配方确定。不得创建电音振荡器、铃声、低鸣、机械弹扣、裂纹扩展、第二次开盒、爆炸、玻璃碎裂、随机爆噪、延迟、混响、语音、旋律自动化或其他揭晓节点。音频能力不存在、浏览器明确拒绝解锁或系统输出静音时，只允许静默省略声音，不得延迟动画、重复请求或改变结果。

## 验证

静态影响域必须通过 Prettier、ESLint、Web TypeScript、架构检查和生产构建。试听 WAV 只用于在开发机确认设计方向、总时长、峰值和无削波，不进入 Web 运行时或部署资源，也不能替代真实设备验收。

真实验收必须在设备取消静音、音量可听且 Safari Web Inspector 关闭时，使用真实 iPhone Telegram 连续执行不同盲盒档次、不同结果稀有度、单抽、十连和“再开一次”。人耳必须确认前四秒每轮都有一强一弱电子心跳、节奏与 13 轮黑洞同步加速、最后阶段不形成刺耳爆音；最后 `700ms` 必须先连续静音 `300ms`，再听到同一次实体扭蛋胶囊开盖动作中的短促气压“啵”和紧接的塑料壳回弹“啪”，声音必须饱满、清楚、轻快而不刺耳，在有声段前约 `105ms` 内收束，后约 `180ms` 不得出现人工尾音；不得听到电音、铃声、机械弹扣、裂纹扩展、第二次开盒、爆炸、玻璃碎裂、低频重砸、固定音高、旋律、长混响或稀有度差异。另开一轮 Inspector 确认 `AudioContext` 运行、没有音频网络请求、揭晓纹理源在 `300ms` 前没有启动且 `0–300ms` 没有揭晓输出，之后只从固定偏移读取一条确定性纹理源，在 `520ms` 停止，并创建 `480 / 1750 / 3400Hz` 三条胶囊弹开滤波支路，不创建揭晓振荡器、第二次纹理源、延迟或混响节点，揭晓调用不接收稀有度、时间轴保持 `4000ms + 300ms + 400ms` 且业务请求没有增加。静态检查、节点存在、普通浏览器试听或开发机 WAV 都不能代替真实 Telegram 主观听感结论。

## 影响边界

- 不改变黑洞尺寸、13 段周期、动画时长、结果图片门控、结果展示、稀有度画面色调、Telegram 触觉、随机、扣款、资格、保底、藏品或任何服务端结算。
- 不新增音频文件、网络请求、数据库、API、RPC、环境变量或持续成本。
- 全部盲盒和结果只维护一套运行时音频配方；后续音色调整必须同步修改本 ADR、产品说明和实现。
