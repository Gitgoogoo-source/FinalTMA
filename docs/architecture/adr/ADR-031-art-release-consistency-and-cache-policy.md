# ADR-031：宠物美术发布一致性与不可变缓存

## 状态

已接受。

## 决定

宠物美术发布、历史回滚与公开对象清理共用数据库中的耐久资源变更租约。任一时刻只允许一个 `publish`、`rollback` 或 `cleanup` 变更处于运行状态；租约带有不可复用的 fence、到期时间和终态审计。发布与回滚 RPC 必须校验匹配且未过期的租约，清理领取也必须先取得同一租约。进程退出后租约可到期接管；旧进程即使恢复也不能凭旧 fence 提交。处于 `deleting` 或 `deleted` 的对象不能被发布流程重新激活。

公开运行时对象从 `catalog/v2/thumb/...` 与 `catalog/v2/detail/...` 命名空间开始发布。对象键包含运行时 SHA-256，上传禁止覆盖，响应缓存必须同时包含 `public`、`max-age=31536000` 与 `immutable`。既有 `catalog/v1/...` 对象不覆盖，作为首个退役批次保留 90 天。资源清单分别保存当前 v2 发布清单和历史 v1 发布清单；Git 仍不保存母版或运行时二进制。

所有可能改变当前批次的命令固定执行以下顺序：取得租约；逐一下载并校验 210 个私有母版和 420 个公开运行时对象的 SHA-256、字节数、格式、尺寸与公开缓存响应头；调用带租约与 fence 的原子发布或回滚 RPC；读取当前批次复核；结束租约。`publish`、`bootstrap` 和 `rollback` 不得绕过该顺序。失败只结束本次租约，当前批次保持不变。

数据库 operation 结果只持久保存模板 ID 和业务结果，不保存宠物图片 URL。`operations.operation_json` 在返回成功结果时根据 use case 和模板 ID 注入当前批次的完整 URL，因此原命令响应、幂等回放和恢复查询使用同一展示入口。开盒结果注入缩略图与详情图，进化结果注入 source/target 两种 URL，市场上架结果注入缩略图。未知 use case 与失败结果原样返回。

资源切换不向已打开页面推送 revision，也不新增 Ably 通知、轮询或聚焦刷新。已经渲染或保存在当前 WebView 内存中的旧 URL 可继续使用；新打开或刷新页面通过 ADR-042 的 `catalog.current` 小指针选择 checksum + release key 不可变目录，切换期间保留上一份成功快照。幂等回放与 operation 恢复继续读取当前批次。发布与回滚不 purge 目录或图片缓存；回滚到旧 release key 直接复用旧缓存，因此不为长驻未刷新页面增加持续网络成本。

## 一致性与失败处理

发布工具只使用 `service_role` 调用资源管理 RPC；浏览器没有这些权限。租约获取、续租、提交和结束均幂等校验运行 ID 与 fence。远端校验分批进行并在批次间续租；任何对象缺失、内容不符、缓存头不符、租约丢失或当前状态复核失败都停止切换。每日清理在租约繁忙时记录为 `skipped`，不会和发布或回滚并发删除对象；Storage 部分删除失败仍由既有对象状态机重试。

v1 与 v2 URL 校验在 90 天保留窗口内同时接受，当前清单、当前发布和新生成对象只能使用 v2。清理仍要求对象不被当前批次引用、全部引用批次已到 `delete_after`、没有有效回滚锁且未被其他清理领取。私有母版不进入清理候选。

## 验证

发布前门禁必须验证当前清单 210/210/420 覆盖、SHA-256、尺寸、体积、MIME、对象键命名空间和公开缓存响应头。数据库从空库重建后先登记并发布历史 v1 批次，再发布 v2 批次，使 v1 获得真实退役时间与 90 天删除时间；随后验证当前 revision、当前 210 条映射、旧批次保护、租约互斥、匿名私有桶拒绝以及浏览器只直接 GET 公开宠物 URL。
