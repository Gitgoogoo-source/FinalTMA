# ADR-080：宠物美术对齐的 Battle 属性重分配

- 状态：已接受；技能有效威力不变条款已由 ADR-095 部分取代
- 日期：2026-08-23

## 背景

当前 `battle-v1` 的部分宠物属性与 `catalog-20260823-png-refresh` 正式图片呈现的元素视觉不一致，例如角色主体、装饰和特效明显属于草系，技能却使用火焰名称与粒子。现有 70 条进化链共 210 个模板；同一进化链的三个阶段必须保持统一属性，并继续共享原角色档案、定位和固定四技能候选池。

产品已逐链审阅全部 210 张正式图片，并批准 `docs/product/功能说明文档.md` 第 21.8.3 节的唯一重分配表。本次只允许重新分配现有技能，禁止新建、删除或改写技能。

## 决策

第 21.8.3 节是 70 条进化链属性分配的唯一事实来源。每条链的三个阶段使用同一个属性；生成器按该属性把原候选池中的数值槽位映射到对应的现有属性技能。本次属性重分配当时保持技能名称、基础威力、命中率、轨迹、阶段技能数量与候选池槽位不变；后续模板有效威力由 ADR-095 单独裁决，不改变本 ADR 的元素映射结论。

P01 至 P14 每个档案继续恰好分配火焰、草系、土系、雷电、水系各一条链。生成器必须拒绝档案缺失、重复档案或同一档案未覆盖五种属性的映射。这个结构同时保证每种属性仍有 14 条链、42 个模板，并保证全部 50 个现有技能各自的模板使用次数与重分配前完全相同。

藏品详情使用的 `apps/web/src/domains/inventory/collection-skills-v1.json` 不再人工独立维护。产品数据构建器必须从同一份 `battle-v1` 模板配置、技能名称和数值槽位生成该文件；只读漂移检查必须在临时目录重建并逐字节比较。数据库种子、Battle JSON/SQL、藏品技能展示和管理员固定验收样例由同一属性分配同步生成或校验，不允许形成第二份映射。

## 不变量

- 210 个模板的 ID、链归属、阶段、稀有度、角色档案、四维、战斗力与定位不变。
- 50 个技能的 ID、名称、元素、数值槽位基础威力、命中率、轨迹和各自使用次数不变；模板有效威力按 ADR-095 固化。
- 一、二、三阶模板仍分别拥有 2、3、4 个技能，同链高阶段只在低阶段技能前缀后增加既定技能。
- 五属性克制关系、伤害公式、Battle 房间、资产、匹配、结算和运行时接口不变。
- 本次不修改任何宠物图片、资源 release、Catalog 模板或图片 URL。

## 验收

生成前后必须按技能 ID 比较 50 个 Counter 并全部相等；同时比较模板稀有度、档案、四维、阶段技能数量和技能数值槽位，任何差异都必须失败。产品数据漂移门禁、数据库 schema 基线、三份原始 migration、TypeScript、ESLint、架构检查、构建与全量静态门禁必须通过。

同一部署 SHA 与同一 Catalog revision 的真实 iPhone Telegram Mini App 必须抽查已改变属性和保持属性的进化链，确认藏品技能名称与正式图片元素一致、1/2/3 阶分别显示 2/3/4 个技能且无旧属性残留。Safari Web Inspector 必须确认当前模板的技能 DOM、接口快照和资源加载正常；本地生成、普通浏览器或部署 READY 不能替代真机结论。
