# ADR-021：开盒像素街机动画、结果舞台与展示门控

## 决定

开盒进行态由 `OperationRegistryProvider` 统一渲染独立的 DOM/SVG 像素街机场景，不使用服务端返回数据生成动画帧，也不修改 `gacha.open` 请求、响应或恢复契约。该 Provider 位于 `AppShell` 外层，操作弹层与 `.app-shell` 是兄弟节点，因此动画使用唯一的 `gacha-hatch-*` 与 `gacha-arcade-*` 全局组件类，不依赖 `.app-shell` 后代选择器。场景使用同一台街机、同一枚盲盒蛋和同一底部中心锚点，通过 `normal`、`rare`、`legendary` 三组 CSS 主题变量切换机台、蛋、能量与爆发光效；灯牌、蛋体、机台、壳片、神秘胶囊和彩纸全部共用一个 3 秒 CSS 时间轴，避免独立帧素材产生轮廓、比例、锚点或周期漂移。结尾只显示带问号的神秘胶囊，不根据真实结果生成预告画面。

街机整体使用一个语义按钮承接连续点击。组件只在 React 内存累计最多 8 格加热状态，普通点击触发 Telegram `impactOccurred("light")`，首次到达满格触发 `impactOccurred("heavy")`；加热状态不进入 operation input、API、恢复摘要或数据库，也不改变 3 秒周期和结果门控。动画即使没有点击也自动完整播放；同一次前端 operation 的后续循环保留加热格，组件卸载后自动清除。

成功结果由 `GachaResultDialog` 在同一全屏像素街机背景上渲染。单抽使用 `image_detail_path` 居中展示一个透明背景藏品主图；十连复制 `result.results` 后仅在展示层按稀有度降序、同稀有度按 `order` 升序，再从底部向上填入顶部 5 个、中间 3 个、底部 2 个的竖向倒金字塔阵型，同一排从左向右排列。阵型使用 30 列网格分别等分出 5、3、2 个居中的位置，并使用统一主图基准尺寸；最前层两个、中间层三个和最后层五个分别通过 CSS `scale` 固定为 `1.2`、`1` 和 `0.8`，稀有度不再参与尺寸计算；阵型容器保持紧凑横向宽度与纵向高度。稀有度最高的两个藏品位于居中的底排和最前层；宠物主图允许轻微横向重叠，稀有度文字保持独立且不得互相遮挡；同屏展示完整结果且不提供横向滚动。每项视觉内容只包含主图、稀有度和既有 NEW 标识；不渲染名称、阶段、数量、抽次、汇总、消耗、资格、保底或 operation id。展示排序不回写 result，不进入确认请求，也不改变 NEW 写入、恢复或再次开盒行为。

新提交的开盒操作在前端以 `operation_id` 独立记录动画档次和周期边界，不使用会被恢复摘要替换的临时 request input 作为展示门控。请求与首轮动画同时开始；成功或失败终态只在首轮结束后的第一个周期边界开放展示。周期边界到达但 operation 仍为 `confirming`、`submitting`、`pending` 或 `unknown` 时，继续下一轮；终态在后续轮次中到达时，于该轮结束后切换到既有真实结果或失败弹窗。同一 operation 被恢复查询回正时不得清除本地周期门控。页面恢复到已经存在的终态 operation 时直接展示真实结果，不伪造一次新的开盒过程；恢复到未决 operation 时继续显示无结论动画和既有轮询恢复。

动画与成功结果舞台共用同一组全屏背景选择器；遮罩承担背景交互隔离，领域操作和底部导航继续使用既有 operation 锁。动画阶段只有街机加热按钮可交互，结果阶段只有竖向倒金字塔结果阵型和既有确认按钮可交互。动画节点不显示价格、扣款、资格、藏品、稀有度、保底、成功或失败结论，不参与业务状态计算。启用系统减少动态效果时，场景固定显示街机、破壳后的神秘胶囊和蛋壳，结果藏品取消入场位移；结果阵型和按钮仍可使用，结果展示仍遵守同一个 3 秒周期门控。
