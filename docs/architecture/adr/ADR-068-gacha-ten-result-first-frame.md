# ADR-068：十连结果首帧预绘制与中心优先显现

## 决定

十连开盒继续在业务请求返回后立即并行加载全部 `10` 张 `image_thumbnail_url`，但揭晓门槛固定只读取排序后最高稀有度藏品、即初始中央项的 `HTMLImageElement.decode()` 结果。中央图未完成解码时，4 秒中性汇聚结束后继续停在不含稀有度的黑洞临界帧；中央图最终失败时继续进入 ADR-021 的同 operation 图片重试舞台。其他九张缩略图不参与金光揭晓门槛，仍在 4 秒演出期间并行下载、有限重试和解码，只有各自解码成功后才取得舞台显示资格。该裁决只改变浏览器表现门控，不改变十连请求、随机、排序、逐抽结果、扣款、保底、库存、图鉴、任务或 NEW 事实。

服务端成功结果到达后，`GachaResultDialog` 继续位于 `GachaHatchAnimation` 的前一个兄弟位置并保持 `aria-hidden`、`inert` 和不可交互，但不再以 `visibility: hidden` 阻止浏览器绘制。中央项与相邻两个已解码项在完全不透明的演出层后方按最终尺寸、最终位置和静态效果真实绘制；演出层显现期间结果层固定为绝对定位和较低堆叠层级，禁止参与父级网格排版、接收焦点或穿透点击。700 毫秒金光结束并移除演出层时，中央主图、身份、标题和操作按钮必须在第一张结果帧中同时可见。

十连舞台的关键过渡只允许动画 `transform` 与已存在的非零 `opacity`，禁止在十个大图层上动画 `filter`、`blur`、`brightness` 或同时为全部图层声明 `will-change`。中央项的入场延迟固定为 `0ms`，相邻项按距中央一层的顺序进入；中央项不得从透明状态开始。十连图层不再为每个结果绘制遮罩光环、落点和双重图片 `drop-shadow`，只在当前中央项使用一个静态径向渐变承接稀有度光晕。

首张结果帧完成后，舞台从中央向两侧逐帧扩大可见半径，每帧最多加入同一距离上的两个已解码图层，直到十个轮播位置全部具备显示资格。未解码图层保持不可见但其原 `CatalogImage` 节点继续加载；后续解码完成时只加入自己的舞台层，不重新开始金光、不重新提交 operation，也不得覆盖当前中央项。横向轮播的十个 snap 位置、中心测量、触觉和服务端结果顺序保持不变。

## 后果

- 图片请求仍与 4 秒演出并行，金光后不新增 `gacha.open`、目录或图片 API 请求；中央项之外的慢图片不再拖住首张结果帧。
- `decode()` 继续作为图片可显示事实，但预绘制把下载解码与最终尺寸的布局、绘制、纹理上传和合成明确分离，避免在金光结束后的同一帧一次处理十个复杂图层。
- 真实验收必须在 iPhone Telegram 与 Safari Web Inspector 中同时检查：一次点击只有一个 `gacha.open`、中央图在金光结束的第一张结果帧可见、标题/身份/按钮没有先于主图出现、剩余图层从中央向外补入、结果切换期间没有超过 `50ms` 的渲染帧中断。静态检查和部署就绪状态不能替代该真机结论。
