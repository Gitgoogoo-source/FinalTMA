# ADR-070：开盒黑洞呼吸同步连续嗡鸣

## 决定

五核及以上设备的前 `4000ms` 中性汇聚音固定改为 Web Audio 现场合成的连续电子低频嗡鸣，完全替换旧的吸入风噪、单向持续升调和三次独立呼吸脉冲。声音与 ADR-067 的 13 段黑洞呼吸使用同一组周期 `800 / 580 / 460 / 380 / 330 / 290 / 260 / 230 / 200 / 170 / 130 / 100 / 70ms`：每轮黑洞膨胀时基频、谐波亮度和响度连续上升，收缩时连续回落；每轮起点与终点仍随整体蓄能逐步抬升，使每次缩放都可听见而整段声音不中断。前四秒不再叠加独立脉冲或随机风噪。最后 `700ms` 随真实稀有度变化的金光揭晓撞击与高频尾音保持原样，不纳入本次替换。

表现模块空闲准备时，以 `2001` 个时间点生成基频、低频、谐波增益和低通截止频率的 `AudioParam` 自动化曲线，每个空闲回调最多计算 `256` 个时间点。黑洞舞台完成全尺寸帧并发布 `data-astral-stage="ready"` 的同一回调立即启动已经准备好的嗡鸣节点，禁止等到后续 React effect 或下一次绘制才开始声音；播放期只创建三个振荡器、增益、低通和动态压缩节点并应用既有曲线，不生成四秒逐样本音频、不读取音频文件、不发起网络请求，也不改变 Canvas 时间轴。玩家点击时仍只解锁 `AudioContext`；曲线尚未准备、音频能力缺失、浏览器拒绝解锁或系统静音时静默省略本次汇聚声，不得在可见动画期间补算曲线。

四核及以下设备继续不创建或解锁 `AudioContext`，不播放汇聚嗡鸣、振荡器或揭晓噪声音效；三个中性 Telegram 选中触觉节点继续保持 `500 / 2000 / 3500ms`，不增加为 13 次。此次裁决不改变黑洞尺寸、呼吸周期、触觉、揭晓音效、动画时长、图片门控、结果展示、业务请求、随机、扣款、资格、保底或藏品结算。

真实验收必须在关闭 Safari Web Inspector 的 iPhone Telegram 中以可听音量连续执行首次开盒和“再开一次”：每轮膨胀的音高与强度必须和画面同步上升，每轮收缩同步回落，13 轮之间不得出现旧式独立脉冲、静音断口或脱离画面的单向升调，最后 `700ms` 揭晓声保持原有撞击与高频尾音。另开一轮 Inspector 只确认没有音频文件请求、`data-astral-breath-periods` 仍为原 13 段且业务请求没有增加；静态检查、构建通过或普通浏览器试听不能替代真实 Telegram 音画同步结论。

## 后果

- 黑洞的每次缩放都具有连续可感知的电子“嗡嗡”反馈，最后四轮的加速同时表现为视觉与听觉的临界频闪。
- 汇聚声仍属于纯表现降级项，任何音频失败都不会延迟或重复 `gacha.open`，也不会改变服务端结果。
- 项目不新增音频资源、下载体积或第三方音频运行时；最后揭晓声的既有实现和稀有度差异保持不变。
