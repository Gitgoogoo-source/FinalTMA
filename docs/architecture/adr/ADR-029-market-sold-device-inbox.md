# ADR-029：市场成交事件游标与当前设备 SOLD 收件箱

## 状态

已接受。

## 背景

市场管理读模型只返回仍有剩余数量的本人挂售。部分成交只能从聚合剩余数量间接看到，全部售罄后卡片消失，因此卖家无法识别每次新成交。产品已经裁决：每次成功交易为卖家生成一张独立 SOLD 卡片，置顶到当前设备用户点击隐藏；Mini App 关闭期间的成交也必须在再次打开后出现，但首次建立本地状态、清缓存或换设备后不补发更早历史。

## 决定

数据库在 `api.market_purchase` 的同一结算事务内，为每名实际卖家写入一条不可变成交事件。`market.seller_sale_sequences` 按卖家保存最新严格递增序号；`market.seller_sale_events` 以 `(seller_id, sequence)` 为主键，并以 `(seller_id, trade_id)` 唯一约束确保同一卖家同一交易只产生一条事件。同一交易从该卖家的多条 FIFO 挂单成交时，先按卖家聚合数量再写事件。涉及多个卖家时按卖家 UUID 稳定顺序锁定并递增序号，避免反向锁序。事件保存模板、真实成交数量、真实成交单价和成交时间，不保存或返回买家身份。

`api.market_create_listing` 在卖家首次上架时保证序号行存在。`api.market_my_listings` 是唯一管理读取 RPC，输入 `p_after_sale_sequence bigint default null`，先对当前卖家序号行取得共享事务锁，再返回当前有效挂售聚合、最多 100 条新成交事件、最新可继续读取的游标与 `has_more`；成交事务只有在挂售和事件均已写好后才更新同一序号行，因此管理读取不会组合“新 SOLD + 旧剩余数量”或“新剩余数量 + 旧游标”。未传游标时返回空事件和当前卖家最新序号，用作本设备首次基线，不补发历史；传入游标时只返回更大序号并按升序分页。HTTP 契约使用十进制字符串传递序号，避免 JavaScript `bigint` 精度丢失。服务端仍通过 session 重新确定卖家身份，前端不能提交卖家 ID。

Web 以版本化 `localStorage` 键和当前 session 的内部用户 UUID 隔离保存 `{ version, cursor, pendingEvents }`。读取后必须逐字段验证，损坏或越界内容整体丢弃并重新建立当前基线。合并响应时按事件序号去重，在同一次本地写入中同时保存新事件与推进游标；本地写入失败时不得只持久推进游标。SOLD 卡片按序号从大到小展示在当前挂售之前，点击整张卡片立即从内存移除并尝试持久化，不调用 API。持久化失败时本次界面仍立即隐藏，但重新加载后允许再次出现。

管理页进入、重新可见、网络恢复时立即读取；页面保持可见且管理页签激活时每 10 秒读取一次，隐藏或切离管理页签时停止。若一次响应 `has_more = true`，Web 立即使用返回游标继续读取，直到追平，再进入 10 秒周期。当前挂售和事件来自同一个 RPC 响应，防止先显示 SOLD 而仍展示旧剩余数量。

本地收件箱不是资产或成交事实，不能确认、删除、撤销或改变服务器记录。它不保存访问令牌、Telegram `initData`、买家身份、余额或库存。清除浏览器缓存、换设备或本地状态损坏后允许丢失旧提醒，并从服务器当前最新序号重新建立基线。

## 结果

卖家可以在当前设备稳定看到 Mini App 关闭期间产生的每笔新成交；部分成交同时回正剩余数量并拆出独立 SOLD 卡片。服务器只保存可分页的成交事件事实，不保存设备是否已读；隐藏状态完全属于当前设备，符合用户已裁决的数据范围。
