# ADR-102：新用户免费普通盲盒

## 决定

自本功能对应数据库迁移生效后，Telegram 用户第一次通过合法 Mini App 入口创建项目账号时，系统在同一个 `api.identity_authenticate` 数据库事务内创建一条 `kind = free_normal_box`、`source = new_user_welcome` 的长期有效资格。直接入口、邀请入口和 Battle 入口使用同一规则；迁移生效前已经存在的账号不回填该资格。

新用户的权威判定只使用 `identity.users` 插入是否成功，不使用前端状态、会话参数或客户端时间。`economy.entitlements` 通过 `user_id` 上限定 `kind = free_normal_box AND source = new_user_welcome` 的部分唯一索引保证每个账号最多一条新手赠礼；Telegram 用户锁、用户表唯一约束、登录幂等记录和该资格唯一索引共同覆盖并发首次登录与网络重试。资格写入失败时账号创建、余额初始化、会话创建和登录记录全部回滚，不产生部分成功。

正常首次认证响应返回 `welcome_reward = { kind: "free_normal_box", amount: 1 }`。同一登录 operation 的幂等重放返回相同字段，即使资格已在本次运行期使用；普通再次登录固定返回 `welcome_reward = null`。API 只转发数据库已经确认的结果，Web 不推断或预先展示赠礼成功。

Web 在主界面准备完成后使用既有非阻塞入口提示展示“免费普通盲盒已到账”。赠礼提示与邀请交接提示同时存在时合并展示，不互相覆盖。提示不自动开启盲盒、不创建开盒 operation，也不把页面切换为其他档次；开盒页没有当前运行期记忆或充值恢复参数时继续默认选中普通盲盒。

该资格复用既有免费普通盲盒消费规则：只可用于普通盲盒单抽，按资格获得时间先进先出，长期有效；匹配资格存在时“开 1 次”优先免费消费，不扣游戏 Stars，不增加、触发或重置任一付费保底。开盒成功后的藏品、图鉴点亮和任务进度仍由既有 `api.gacha_open` 单事务裁决。

本功能不新增浏览器直连数据库、公开 RPC 或独立奖励领取接口。服务端继续只以 `service_role` 调用显式授权的认证 RPC。

## 验证

数据库验证覆盖迁移从既有版本向前应用、首次创建一条资格、同 operation 重放、不同 operation 再次登录、同 Telegram 用户并发首次登录、存量账号不回填、资格消费后再次登录不补发，以及免费普通单抽不扣 Stars、不改变付费保底。接口与 Web 验证覆盖严格响应契约、首次提示、邀请提示合并、普通档默认选中和免费次数显示。上线验收使用真实 iPhone Telegram Mini App 与 Safari Web Inspector，同时核对请求、控制台和数据库最终事实。
