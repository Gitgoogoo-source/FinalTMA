# ADR-037：持久页面查询活动边界与缓存回正

## 状态

已接受。

## 决定

交易、游戏、开盒、藏品和任务五个主页面继续在当前 session generation 内首次访问时挂载，之后不因主导航切换卸载。路由层为每个持久页面同时提供页面交互活动状态和页面查询活动状态；页面可见时两者为活动，页面隐藏时两者为非活动。`useApiQuery` 的最终启用条件固定为调用方声明、页面查询活动状态和查询抑制状态三者同时允许。查询活动上下文在持久页面外默认活动，因此顶部资产、支付恢复、统一操作恢复、全局弹窗和图鉴覆盖路由不会因主页面切换被暂停。

页面隐藏只停止后续自动查询，不取消切换前已经发出的 GET。已经开始的读取允许完成并写入同一 session generation 的查询缓存，避免共享查询键被取消、观察者状态回滚或快速往返切页形成中止竞态。隐藏页面的 DOM 继续使用 `hidden` 与 `inert`，不能从隐藏界面触发手工刷新。Session generation 改变、身份恢复失败、会话清理或账号封禁仍取消旧 generation 查询并清空全部页面和查询缓存。

React Query 的 `staleTime` 固定继续为 20 秒。隐藏页面重新可见时，未失效且仍新鲜的缓存直接使用，不发出查询；已超过 20 秒或被业务刷新范围标记失效的查询在本页重新活动后按每个查询键发起一次回正。已有缓存必须先立即渲染，回正成功后替换为最新权威状态。回正失败且已有缓存时不得清空页面或展示原始错误，只保留现有内容，并显示非阻塞的“内容暂未更新”和“重新加载”；手工重试期间按钮锁定为“正在更新”。首次读取失败且完全没有缓存时继续使用该领域既有的初始加载失败界面。

`invalidateApiQueries`、`refreshUserState` 与 `refreshScopes` 固定把所有匹配的当前 generation 查询标记为失效，并使用 `refetchType: "active"`。当前可见页面和持久页面外的活动查询立即重新读取，其失败继续按调用方既有规则传播；隐藏页面查询不读取、不参与等待，但保留失效状态，返回页面后再回正。统一 operation authority cursor 在当前可见页面和全局活动查询完成、隐藏查询已被标记失效后可以推进；隐藏查询不得阻塞当前操作结果或导致同一终态被反复发现。数据库、RPC、API 权限、业务事务、幂等键和资产裁决不变，玩家基于旧缓存发起的动作仍由服务端重新验证并以数据库结果为准。

身份域的可刷新查询固定只有 `identity.summary`。顶部人工刷新只读取它与 `vip.get`；前台恢复和 `assets`、`inventory`、`payments`、`mint` 刷新范围使用精确 route ID 命中 `identity.summary`，不得使用整个 `identity` 前缀。`identity.initial` 是入口恢复快照，不注册 React Query，不参与 `refreshUserState`、`refreshScopes`、前台恢复、页面重新激活、Battle 终局或 Mint 恢复。

Battle 的查询启用、Realtime、presence lease、heartbeat、offline 与权威轮询继续同时受 Battle 自身页面活动规则控制，不以通用缓存提示替代 Battle 的静默回正。市场 SOLD 收件箱继续同时受交易页可见性、Telegram 活动状态、文档可见性和网络状态控制；交易页隐藏后停止轮询，重新可见时立即读取。已经使用领域内非阻塞缓存提示的管理页和开盒页保留其既有文案与恢复动作，不叠加第二个提示。

页面组件状态和查询缓存仍只存在于 JavaScript 内存，不新增 `localStorage`、`sessionStorage`、IndexedDB 或服务端缓存。市场 SOLD 收件箱按 ADR-029 保持唯一既有本地持久化例外。

## 原因

主页面保活用于保存滚动、筛选、选择和未提交界面状态，但仅使用 `hidden` 与 `inert` 不会停止已挂载 Hook 的查询观察者。业务结果的宽刷新范围因此会把当前页面动作放大为多个隐藏页面读取。统一查询活动上下文把“保留界面状态”和“允许自动读取”分开，覆盖当前及未来嵌套查询，同时保持全局恢复和覆盖路由活动；显式 active-only 失效语义则让全部相关缓存保持一致的失效标记，而不为不可见内容消耗网络与电量。

## 验证

静态门禁必须证明五个持久页面均接入查询活动 Provider、`useApiQuery` 同时检查页面活动和查询抑制、Provider 默认活动、三个公共失效入口显式使用 active-only refetch、稳定 refetch 包装保留 `cancelRefetch: false`，并保持 Battle 与市场 SOLD 的领域活动门控。

真实开发环境使用同一部署 SHA 在 Telegram iOS 与 Android 验证：五页状态和滚动保持；隐藏页除切页前已开始的读取外没有自动页面查询；20 秒内返回新鲜页不读取；过期或失效页返回后每个查询键只回正一次；弱网回正失败保留缓存和非阻塞重试；首次无缓存失败仍显示领域初始错误；顶部资产、支付和统一操作恢复不中断；市场 SOLD 轮询与 Battle 生命周期继续遵守各自裁决。静态检查、构建成功和普通浏览器结果不能替代真实 Telegram 网络记录。
