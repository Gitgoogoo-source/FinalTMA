# ADR-023：全局顶层业务弹窗

## 决定

普通业务弹窗统一使用共享 `AppModal`。`AppModal` 通过 React Portal 挂载到 `document.body`，不把遮罩或弹窗面板留在五个主页的滚动容器内；普通业务弹窗固定使用应用层级 `120`，高于顶部资产栏、底部导航、页面浮层和普通通知。操作恢复弹窗固定使用层级 `160`，确保需要操作状态层的命令在普通业务弹窗上方展示结果；签到、任务领奖、VIP 日领、远征创建与领奖、市场上架/下架/购买改用不锁定页面的轻提示，仍通过原操作注册表提交、验证与恢复，市场上架及购买仍等待权威刷新后才提示成功。Battle 强制全屏状态继续使用其专用层级 `200`。

`AppModal` 打开时将真实主应用外壳设为 `inert`，锁定应用内容、`html` 与 `body` 滚动，把焦点移动到弹窗内第一个可操作控件，并将 `Tab` 焦点限制在弹窗内。关闭时按引用计数恢复外壳原始 `inert` 状态、滚动设置和打开弹窗前的焦点。仅当调用方提供关闭动作时，`Escape` 才执行该动作；支付确认中、业务提交中等不可关闭状态不提供关闭动作。

遮罩覆盖整个稳定视口，并按设备左右安全区和底部安全区计算内边距。普通弹窗面板的最大高度使用 Telegram 稳定视口减去上下安全区与固定外边距，超出时只滚动面板内部，底部导航始终位于遮罩下方且不能交互。

进化确认和分解确认使用暖白底、橙色主按钮的共享藏品操作底部弹窗，宽度不超过应用内容区，高度随内容变化并受稳定视口约束；正文独立滚动，操作区固定在底部并包含安全区。标题精简为图标、动作名称与必要说明。数量、成本、概率、失败损失和提交行为仍由原领域组件提供。藏品出售直接进入市场出售页面，在该页设置数量，不再先出现数量弹窗。

VIP、分解、远征、市场购买与下架、充值、钱包和进化确认全部接入 `AppModal`。图鉴详情继续使用浏览器原生 `dialog.showModal()` 顶层；当前盲盒页面不再打开独立奖池弹窗；Battle 弹窗已经使用独立 Portal 和背景锁定；需要玩家查看或确认的操作恢复弹窗位于页面外并锁定全局导航；轻提示不锁定导航，未确定结果保留原操作锁及查看结果入口。这三类继续保留其已确定机制，不再套入第二层普通业务弹窗。

充值与 VIP 弹窗组件及所属 CSS 不进入首屏同步闭包。顶部按钮在 `pointerdown`、键盘 `focus` 与实际打开时复用同一动态加载 Promise；支付恢复需要打开弹窗时走同一入口。加载超过短暂等待后，在目标面板展示骨架占位；充值保持透明且不模糊的遮罩；加载失败保留支付订单和导航意图，只允许重新加载弹窗模块，不创建订单、不重提支付或业务命令。普通弹窗的 Portal、`inert`、焦点、滚动锁、安全区和层级规则不因异步加载改变。

## 原因

五个主页的内容区域使用独立纵向滚动和 iOS 原生惯性滚动。WebKit 会为该滚动路径建立独立层叠上下文，页面内部的固定定位弹窗即使具有高于底部导航的局部 `z-index`，也不能越过外部导航所在的层叠上下文。将业务弹窗统一 Portal 到 `document.body` 后，弹窗、顶部资产栏和底部导航在同一顶层关系中比较，层级、背景锁定、焦点和安全区行为由一个组件确定。

2026-09-10：轻提示只有已验证成功才自动收起；失败、处理中或结果未知不会按成功通知自动消失。轻提示在普通弹窗开启时挂入其焦点范围，允许键盘收起和查询。技术错误仅通过前端错误码白名单映射为玩家文案，原始服务端 message 不进入玩家界面。进化与分解仅在已获得确定结果后允许跳过剩余动画，进化 ACK 和业务终态不因跳过动画改变。
