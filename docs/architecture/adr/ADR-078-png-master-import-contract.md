# ADR-078：宠物 PNG 原图导入与 WebP 母版契约

- 状态：已接受
- 日期：2026-08-23

## 背景

宠物运行时只接受受控发布的 WebP，但本轮 210 张新设计原图是带透明通道的 1024×1024 PNG。直接人工重命名、逐张转换或覆盖旧 Storage 路径无法证明图片与 Catalog 模板的一一对应，也无法保证尺寸、透明度、转换参数、元数据和正式发布字节一致。

## 决策

每次整体换图只接受恰好 210 张单帧、1024×1024、8-bit sRGB RGBA PNG。文件名固定为 `NNN_CNNN-S_<当前 Catalog 名称>.png`：`NNN` 是 `001` 至 `210` 的全局 `sort_order`，`CNNN` 是模板所属进化链编号，`S` 是 `1` 至 `3` 的阶段。工具必须同时核对四项身份；只允许从名称两端移除误带的 Unicode 空白与下划线，不改变中间字符，不修改原文件名或原图。PNG 以外的同目录文件不参与导入。

每张输入必须同时满足：Sharp 能严格解码；格式为 PNG；色彩空间为 sRGB；四通道、`uchar` 深度、每采样 8 bit、单帧并带 alpha；画面同时存在完全透明像素和可见像素；四个画布角点完全透明。任一输入失败、缺失、重号、序号不连续、链/阶段/名称不匹配或输出目录非空时，整批禁止生成资源清单与发布。

通过校验的 PNG 保持完整正方形画布，以 Lanczos3、`fit: fill` 从 1024×1024 缩放到 768×768，并编码为 lossless WebP，`effort = 6`、`alphaQuality = 100`。不得裁切、trim、补边、旋转、改变主体构图或写入 EXIF、ICC、IPTC、XMP、文本注释及其他源元数据。每张母版必须是带 alpha 的单帧 768×768 WebP 且不超过 2 MiB；随后按 ADR-010 的唯一参数生成公开缩略图和详情图。

`prepare-png` 必须使用彼此独立的 PNG、母版和运行时目录，且两个输出目录在开始时为空。原 PNG 始终只读，不上传 Supabase、不纳入 Git。工具按 Catalog 顺序为每张 PNG 记录原文件名、输入 SHA-256 和字节数，再对确定性记录计算整批 `set_sha256`；资源清单保存该集合哈希、输入契约和母版转换参数，并继续保存 630 个输出对象的 SHA-256、尺寸和字节数。既有生产 Storage 继续使用上线前已验收的同一母版和运行时字节，禁止重新转换、覆盖或复制到第二个项目。

## 发布一致性

新批次继续使用内容哈希对象键和 `upsert = false`，不覆盖旧对象。只有 210 张母版、210 张缩略图、210 张详情图全部通过本地与远端校验后，受控发布 RPC 才能原子切换当前 Catalog 资源 revision。任何导入、转换、上传或验证失败都保持旧批次为当前事实；历史私有母版和旧公开对象继续遵守 ADR-010、ADR-031 的保留与清理规则。

## 验收

发布前必须复算原 PNG 集合哈希，证明导入前后原图未变；校验全部输出的格式、尺寸、alpha、元数据、单文件上限、运行时总上限和内容唯一性，并在浅色与深色背景下检查完整 210 张接触表。云端切换后必须复核当前 release key、manifest SHA-256、revision、420 条公开 URL、MIME、尺寸、SHA-256 和不可变缓存头；最后在同一部署与同一 Catalog revision 的真实 Telegram iPhone Mini App 中检查使用宠物图的用户界面，并以 Safari Web Inspector 排除资源请求、解码、CSP 和控制台错误。不得以本地生成成功替代真实客户端验收。
