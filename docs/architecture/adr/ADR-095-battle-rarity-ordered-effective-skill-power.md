# ADR-095：Battle 同阶段跨稀有度技能有效威力

- 状态：已接受
- 日期：2026-08-30

## 背景

`battle-v1` 原先把 10 个数值槽位的 `power` 直接返回页面并用于伤害公式。14 个角色档案的候选池只保证单个模板内部按基础威力非降序，不保证同阶段、同技能位置的跨稀有度关系。全量 210 模板检查确认三个阶段都存在高稀有度有效威力低于或等于低稀有度的情况；例如普通链第 2 阶 Slimeshard 为 `45/70/85`，顶级链第 2 阶 Azureoracle 为 `60/70/75`。

产品已裁决：同一阶段、同一技能位置，稀有度越高，宠物页面与技能按钮显示的威力必须严格更高；实际结算仍由攻击、防御、属性克制和单次伤害上限共同决定。

## 决策

技能槽位继续保留现有基础威力、命中率、轨迹、名称和元素。候选池继续按基础威力排序，技能 ID 和使用次数不变。生成器在技能顺序确定后，按链类型和技能位置应用以下有效威力下限：

| 链类型 | 档案    | 位置 1 | 位置 2 | 位置 3 | 位置 4 |
| ------ | ------- | -----: | -----: | -----: | -----: |
| 普通链 | P01—P08 |      0 |      0 |      0 |      0 |
| 高级链 | P09—P12 |     71 |     81 |     96 |    126 |
| 顶级链 | P13—P14 |     72 |     82 |    106 |    127 |

每个模板位置的有效威力固定为 `max(基础威力, 位置下限)`。普通链保留原值；高级链下限逐位置只比普通链最大值高 1；顶级链下限逐位置只比应用下限后的高级链最大值高 1。该方案是满足严格递增、只允许上调、保留技能 ID/顺序以及同链阶段前缀的逐位置最小整数解。

生成器把有效威力与技能 ID 并列写入 210 个模板配置。数据库在创建房间时把两者一同复制到 `battle.team_members` 不可变配置快照；队伍选项、藏品技能详情、己方队伍 DTO 和伤害公式都读取同一份固化有效威力。浏览器不根据稀有度、阶段或链类型计算威力，数据库结算也不回读客户端值。

## 不变量

- 同一阶段的每个技能位置都满足低稀有度最大有效威力 `<` 相邻高稀有度最小有效威力。
- 每个模板的有效威力数组按位置非降序，且每项不低于对应数值槽位基础威力。
- 同一进化链低阶段的技能 ID 和有效威力数组同时是高阶段前缀，进化不改变已拥有技能的威力。
- 技能名称、元素、命中率、轨迹、候选池、技能使用次数、角色档案、四维、Catalog、图片和经济数据不变。
- 最终扣血继续由模板有效威力、攻击、防御、属性克制和 80% 单次伤害上限共同裁决，不承诺任意不同对局中的最终扣血保持稀有度排序。

## 验证

产品数据生成器和数据库 `battle.rules_complete` 必须分别拒绝任一跨稀有度相等或倒挂、有效威力低于基础威力、模板内部倒序、技能/威力空值错位或同链阶段前缀漂移。真实开发数据库必须从空库重放完整 migration；API 返回值、藏品页面和 Battle 技能按钮必须来自同一权威有效威力。最终验收使用真实 iPhone Telegram Mini App，并通过 Safari Web Inspector 核对页面 DOM、接口响应与一次真实伤害结算；本地生成、静态检查或 Vercel READY 不能替代真机结论。
