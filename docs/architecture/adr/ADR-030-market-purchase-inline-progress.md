# ADR-030：市场购买按钮内进度与专用结果弹窗

## 状态

已接受。

## 背景

市场购买确认页原先在用户点击“确认购买”后立即关闭，再由全局操作注册中心展示 `market.purchase` 的通用状态弹窗。该通用弹窗会把“服务器确认”、等待说明和 operation ID 暴露给玩家；成功后仍复用同一技术状态界面，也无法形成产品裁决要求的独立购买成功反馈。

购买仍是 operation-backed 幂等写操作，不能因为移除通用弹窗而绕过原 UUID、未知结果查询、服务端裁决或权威状态刷新。前端也不能在请求完成前自行宣告成功。

## 决定

`market.purchase` 继续统一进入 `OperationRegistryProvider`，沿用同一 operation UUID、同一 `use_case` 重复提交锁、`pending`/`unknown` 自动查询和路由 refresh scope。注册中心在 `confirming`、`submitting`、`pending`、`unknown` 阶段不挂载全局操作状态弹窗；购买确认弹窗保持打开，数量调整、取消和确认按钮全部锁定，原确认按钮只显示“购买中”。

当前前台运行期取得明确成功结果后，必须先校验 `market.purchase` 输出 Schema 并完成路由声明的权威刷新。随后操作进入 `succeeded`，购买确认弹窗关闭，注册中心打开专用结果组件。该组件只使用已校验结果中的购买数量与提交时保存在当前内存 operation presentation 中的藏品名称，固定展示标题“购买成功”、正文“已成功购买 N 个藏品名称”和按钮“完成”；不显示服务器、请求、operation ID、卖家或调试信息。“完成”只移除当前 Web 内存中的结果展示，不发送 API 或 RPC。

明确失败进入不含技术信息的专用失败弹窗，并在权威刷新后允许玩家按最新库存和余额重试。网络中断或暂时未知时不生成新幂等键，保持“购买中”并自动查询原 operation。页面隐藏、Telegram `deactivated`、刷新、关闭或重新进入后，当前购买结果展示资格被丢弃；恢复链路只查询原 operation、刷新权威状态并静默移除操作锁，不恢复旧成功或失败弹窗。

## 结果

玩家在购买处理中只看到原确认按钮的“购买中”反馈，成功后只看到独立、简洁的购买成功弹窗。技术状态和 operation ID 不再进入市场购买界面，同时数据库裁决、幂等、未知结果恢复和前端权威回正边界保持不变。
