# ADR-012：进化共享藏品操作底部确认弹窗

## 决定

进化确认通过全局 `AppModal` 的 React Portal 挂载到 `document.body`，并以高于顶部资产栏、藏品列表和底部导航的固定层级覆盖主应用稳定视口。遮罩保留全局顶部资产栏、藏品页和底部导航可见，但由共享顶层弹窗机制将这些背景内容全部设为不可交互。进化确认接入 [ADR-023](ADR-023-global-modal-layer.md) 定义的共享藏品操作底部弹窗：面板固定停靠在底部，宽度等于应用内容宽度，高度取当前动态视口的 `68%` 与 `720px` 中的较小值；顶部两角使用 `34px` 圆角，底部操作区自行包含设备底部安全区。

进化、出售数量和分解确认共用同一张透明云朵装饰资源。云朵、暖金星光和橙色碎屑保持可见，三个弹窗不展示大功能图标；面板使用暖白底色，遮罩使用半黑背景与克制模糊。该共享视觉只改变布局与表现，不改变任何业务信息、校验、按钮步骤或提交路径。

弹窗由固定标题区、独立滚动的进化内容区和固定操作区组成。内容区按“上方材料 1、中央目标、左右材料 2/3”的关系展示固定 3 个材料格；材料格按页面已有可用数量依次填充，批量数量选择仍以 3 为步进。取消与“开始进化”按钮始终固定在弹窗底部。共享顶层弹窗机制在打开时锁定应用背景、`html` 与 `body` 滚动并限制焦点，关闭时恢复打开前的滚动与焦点；`Escape` 只执行取消，不提交进化。

Catalog v1 的 140 条进化路线在产品数据构建时生成精简前端静态清单并随 Web 打包。确认弹窗只从该清单读取目标藏品、稀有度变化、基础成功率与每次 Fgems，从页面已加载状态读取可用数量和 Fgems；点击外层“进化”不调用服务端预览接口。界面不展示实时保底进度或本次必成状态，前端静态数据只负责展示和预检查。只有点击“开始进化”才提交模板 ID 与材料数量；最终保底、库存、余额、扣除、目标发放和结果继续由现有 `inventory.evolve` 操作、数据库事务与进化恢复工作流裁决。既有 `inventory.evolution_preview` 仅为旧 Web 版本兼容保留，不是当前 Web 的打开弹窗路径。
