# ADR-094：Battle 行动截止门禁与冲突恢复

- 状态：已接受
- 日期：2026-08-29

## 背景

Battle 数据库为每个当前行动者保存唯一 `phase_deadline`，并在 room-first 锁内拒绝 deadline 之后到达的动作。既有 Web 倒计时只负责显示和到期读取：攻击、主动换宠与换宠反击的可用条件没有包含倒计时，三个最终提交入口也没有截止复核。因此，页面显示 `00:00` 后仍可能短暂保留可点击控件并提交旧 `(round_no, action_ordinal)`；数据库随后正确返回 HTTP 409 / `BATTLE_STATE_CONFLICT`。该拒绝没有创建第二个动作，根因不是数据库重复结算，而是客户端展示时钟、交互门禁与服务端 deadline 没有形成同一边界。

同时，Battle JSON 的 `server_time` 使用 PostgreSQL `now()`。它固定为事务开始时间，不能表示快照完成构造时的实际时刻；当业务事务持续数百毫秒时，客户端收到的剩余时间会比数据库真实剩余时间更长，扩大上述旧动作提交窗口。

## 裁决

数据库继续拥有完整 15 秒及最终裁决权，不缩短 `phase_deadline`，客户端不增加提前截止缓冲。所有 Battle 对外 JSON 的 `server_time` 固定使用 `clock_timestamp()`，表示该响应字段实际构造时的时刻；直接调用该时钟的 JSON helper 必须声明为 `VOLATILE`，不得以事务起点 `now()` 伪装响应时刻。业务 deadline、presence、到期与锁内比较仍使用既有事务一致性语义，不随本裁决改变。

Web 以同一快照的 `server_time` 和 deadline 建立时钟锚点，以单调时间推进，并以墙钟经过量覆盖 iOS 页面挂起期间单调时钟可能停止的区间。显示每 250 毫秒更新，另设精确 deadline 定时器；`visibilitychange`、`pageshow` 与 `focus` 立即重新计算，既有前台恢复继续执行单次权威 REST 回正。剩余时间大于零是技能、主动换宠、换宠反击和换宠弹层共同的必要条件；达到零的同一次前端更新立即隐藏操作控件、关闭换宠弹层并显示“本次行动时间已结束”。

攻击、主动换宠与换宠反击的最终事件处理函数在任何本地表现或网络提交之前，使用同一时钟锚点重新检查 deadline。为保留前端先行反馈，命令允许等待一个绘制帧，但必须在真正调用网络层前再检查一次同一锚点；第二次检查失败只撤销临时状态，绝不发送 `battle.action`。截止前已经进入网络层的请求保持在途，不因倒计时随后归零而取消；它最终由数据库按真实到达和锁内状态裁决。

`BATTLE_STATE_CONFLICT` 保持 `retryable = false`。`battle.action` 收到该错误时不得重放、不得生成新幂等键，也不得通过通用 scope 再触发第二轮刷新；它只进入 BattleView 既有 single-flight 权威协调器读取一次当前状态。倒计时到期、前台恢复、Realtime 失效和冲突同时发生时复用同一个在途读取。错误码和内部信息不渲染给玩家，未获确认的本地临时表现撤销后只展示游戏内权威状态。

## 结果

玩家获得数据库裁决的完整 15 秒；页面在本地倒计时归零后不再制造必然过期的动作请求，而极端传输边界仍由既有 409 安全拒绝。预截止在途动作、幂等语义、超时技能位置 1、固定先手、行动顺序、伤害、资产与结算规则均不改变。

静态门禁必须证明 Battle 的六处 `server_time` 均使用 `clock_timestamp()`、不存在 `server_time = now()`，并证明三个动作入口和操作区共享 deadline 门禁。真实 iPhone Telegram 与 Safari Web Inspector 必须覆盖攻击、主动换宠和换宠反击在 `00:01 → 00:00` 的边界：到零立即无可操作控件，零点后点击不出现 action POST；截止前提交只出现一次 POST 且允许完成；构造真实冲突时只出现一次 409 和一次合并后的权威读取，不出现 action 重提、错误浮层或重复数据库动作。
